# K3：工具结果假设与 Hybrid 重算（0.37.0）

管理员可以从当前版本的固定 Hybrid 预览中选择一条工具结果，填写完整替换文本，保存独立假设预览，再启动模型重算。原录制不改写。假设与原录制回放、真实工具执行分别标记；这是受控反事实实验，不是对外部世界的验证或质量评分。

需要 RunDesk 0.37.0、Kun 0.12.0、worker 协议 v12、fork schema 3。两个二进制一起升级。旧执行记录和分支对照可只读查看；旧检查点或预览不能跨版本执行，也不能转换成新假设。先完成本版普通运行并生成新的 Hybrid 预览。

## 操作

1. 打开一个**尚未修改工具结果的 Hybrid 固定预览**。父分支不需要先启动。
2. 在“修改工具结果 → Hybrid 重算”点击“读取可替换结果”。显示所选安全点之后的录制顺序、工具、原状态、完整输出指纹和有界节选。
3. 选择一条结果，填写标题、替换理由和**完整新输出**。允许明确的空字符串；不会把截断或脱敏的原文节选自动填成替换值。切换结果会清空尚未保存的替换文本。
4. 点击“保存假设固定预览”。此步不创建执行会话，不启动 worker、模型、工具或外部连接。新预览继承父级补充指令、原始执行快照和预算。
5. 核对新预览中的替换全文、理由、父预览及指纹，再点击“启动或打开 Hybrid 分支”。这一步会调用模型并消耗用量。每份预览只运行一次；重复提交返回同一目标。
6. 读取“来源与分支对照”，可选择父预览对应的执行结果作左侧。查看“原录制回放”“假设替换”“真实派发”计数及假设使用状态；“查看假设结果事件”定位实际使用证据。

每个子预览只替换一个结果；如需另一个假设，从未修改的父预览重新创建。不支持 Live、叠加替换、修改工具参数/身份/成功失败状态、执行嵌套分叉，或导入 K3-A 的脱敏文本实验。完整依赖图、多结果编辑、实验清理和独立评分仍未实现。

## 执行与证据

私有 bundle 保留原始 `records`，新增 `hypothesis` 叠加项。它绑定父预览 ID/哈希、父 bundle 哈希、零起始录制位置、来源序号、完整原录制指纹、原/新输出指纹、理由和替换全文。子 bundle、公开预览和固定目标都有新身份。所有哈希受完整预览校验保护；worker 在执行前另行验证叠加项和原录制绑定。

`recordHash` 是原 ReplayRecord 的标准 JSON 编码 SHA-256；`originalOutputHash` 和 `outputHash` 是各自完整 UTF-8 文本字节的 SHA-256。父 bundle 去掉叠加项后必须恢复原 bundle 指纹。替换值与原文完全相同时拒绝保存，避免把未改变的输出误标成实验变化。

Hybrid 仍只匹配**下一条**录制的工具身份、schema、规范化参数、环境和目录，不向后搜索，不进行真实工具派发，不连接 MCP，不读写项目文件。未命中以 `replay_miss` 停止。工具的 `status`/`isError` 保留，因此把失败文本改写成成功措辞不会把工具变为成功。

运行系统说明明确人工假设的位置及其未验证性质。只有执行到选定位置且匹配成功时才替换模型收到的 tool 文本；假设并不保证一定被使用。`kun/tool.completed` 仍为 `status=replayed`，`replay.mode=hypothetical`、`executed=false`，附来源位置、原/新输出和假设指纹。其他结果保持 `mode=recorded`。两者均消耗继承预算下的工具额度。

| 对照状态 | 含义 |
| --- | --- |
| `applied` | 所选固定宿主范围内已有匹配假设指纹的完成事件，返回事件 ID；即使后续日志尚未完整，也能证明这次使用 |
| `not_reached` | 启动来源、继承预算及连续结束日志均完整，范围内没有使用此假设 |
| `unknown` | 未运行、日志缺失/未同步完整或尚未结束，不能断言是否最终使用 |

固定上界为零时始终是未记录；新事件须显式刷新。日志删除不会被视为“假设未使用”。假设输出和理由不进入对照摘要；模型回复仍按既有有界回复规则显示，可能包含模型引用的文本。

## API、边界与保留

| 管理员 API | 作用 |
| --- | --- |
| `GET /api/v1/kun-forks/recordings/{fid}` | 返回 `previewId/previewHash/items`；每项含位置、来源序号、工具、原状态、recordHash/outputHash、字节数、节选及脱敏/截断标记 |
| `POST /api/v1/kun-forks/{fid}/hypotheses` | 请求 `expectedHash, position, recordHash, output, reason, title`；要求 `Idempotency-Key`，创建固定子预览 |
| `GET /api/v1/kun-forks/{fid}` | 子预览详情包含用户填写的完整假设文本和理由；列表省略这两项 |
| `POST /api/v1/kun-forks/{fid}/start` | 沿用 `expectedHash` 与单目标幂等执行；假设只能 Hybrid |
| `GET /api/v1/kun-forks/comparisons/{fid}` | 新增 `tools[].hypothetical` 与 `hypothesis` 指纹/状态/证据摘要；`replayed` 仅计原录制回放 |

应用 key、成员 runner/viewer 和成员代理均拒绝。HTTP 不接受可执行 bundle，K3-A 的宿主脱敏事件不能替代权威私有录制。父预览和原始数据保留；来源删除、父目标删除或宿主重启不改变已保存的子预览。启动仍核对当前配置、工作区存在性和执行容量；目标删除后该子预览不重建。

最多 128 个录制结果；展示每项最多 2048 Unicode 字符。可解析 JSON 的常见凭据字段脱敏，任意自由文本无法保证自动识别。摘要不含完整消息历史、工具参数或执行包。新输出最多 **64 KiB UTF-8 字节**，理由 1–1000 字符，标题沿用 120 字符限制；空 output 必须显式传 `""`，缺省/null 拒绝。添加叠加项后的整个 bundle 仍不能超过 4 MiB。

本地内核、真实 worker、HTTP、权限与 Node 交互验证见 [KUN-VALIDATION.md](KUN-VALIDATION.md)。真实浏览器布局、真实远程服务、Windows 实机和生产验收未完成。
