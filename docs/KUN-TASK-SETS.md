# K3：固定输入任务集（RunDesk 0.39.0）

把多个案例的输入与验收规则保存为一份不可变定义，供后续重复运行使用。当前提供创建、完整查看、分页列表与复制为新草稿；不启动会话，不调用模型或工具，也不生成评分结果。

这是多案例评测的定义层。批量执行、运行与任务集的服务端绑定、逐案例结果收集、汇总评分、多次采样和独立验证集隔离尚未接入，不能凭保存任务集认定 K3 评测或 K4 已完成。0.38 的固定日志评分仍独立使用，任务集暂不自动转换为其同基线 rubric。

## 界面

1. 在管理员工作台点击“评测任务集”。
2. 填写任务集标题，为每个案例填写唯一标识、标题、固定输入和文本验收规则。
3. 点击“保存固定任务集”。保存保持输入与规则的原始空白、大小写和 Unicode 内容；没有自动运行。
4. 点击“读取任务集列表”，选择一份任务集查看全文、时间、ID 和内容指纹。列表不加载案例正文。
5. 修改已有任务集时，点击“复制为新草稿”，编辑后再次保存。生成新 ID 和指纹，原定义保留。

每个案例的文本规则复用 `reply-rules-v1`：包含、不包含、完全等于；另固定要求运行成功结束。此处只保存规则，匹配语义见 [固定规则评分](KUN-EVALUATION.md)。

## API

全部为管理员专用；应用凭据和成员入口均不可访问。

| 操作 | 含义 |
| --- | --- |
| `POST /api/v1/kun-task-sets` | 只接受 title/cases；必需 Idempotency-Key；保存新的不可变定义 |
| `GET /api/v1/kun-task-sets?offset=0&limit=20` | 按创建顺序倒序分页，只返回 id/hash/title/createdAt/caseCount |
| `GET /api/v1/kun-task-sets/{tid}` | 返回完整固定定义，并校验持久化指纹和结构 |

旧 `/api` 前缀兼容。POST 同一 Key 与同一请求返回同一对象；Key 用于不同请求返回 409。无原位修改、删除、执行或评分接口。服务端生成 schema=1、evaluator=reply-rules-v1、ID、创建时间、案例数与整体 SHA256 指纹；用户不能提交这些字段。顺序也是固定定义的一部分。

示例请求体：

```json
{
  "title": "库存建议",
  "cases": [
    {
      "key": "stocked",
      "title": "库存充足",
      "input": "库存为 100，请给出建议。",
      "rules": [{"kind": "reply_contains", "value": "充足"}]
    },
    {
      "key": "empty",
      "title": "库存为零",
      "input": "库存为 0，请给出建议。",
      "rules": [{"kind": "reply_contains", "value": "补货"}]
    }
  ]
}
```

## 边界与校验

| 内容 | 限制 |
| --- | --- |
| 每集案例数 | 1–20，保留顺序 |
| 案例标识 | 1–64 位 ASCII 字母、数字、点、下划线或连字符；以字母/数字开头；同集中唯一、大小写敏感 |
| 任务集及案例标题 | 各 1–120 Unicode 字符，不能全空白 |
| 每案例固定输入 | 非空白有效 UTF-8，最多 8192 Unicode 字符 / 32 KiB |
| 每案例规则 | 1–12 条；每条最多 2048 字符 / 8192 字节；规则文本合计最多 16 KiB；完全重复规则拒绝 |
| 整集文本 | 标题、案例标识/标题/输入、规则 kind/value 的 UTF-8 字节合计最多 256 KiB；HTTP JSON 请求仍受全局 1 MiB 上限 |
| 列表 | 默认 20，每页最多 50；offset 0–20971520；未知或重复查询参数拒绝 |

不执行输入、规则脚本或正则。保存/查看不访问项目文件或运行日志，不依赖既有会话。已保存定义在宿主重启后保持一致；复制使用完整文本，客户端不提交旧 ID/hash。持久化内容被修改或 schema/evaluator 不兼容时返回 409。没有任务集删除或自动留存清理。

本批验证与阶段完成度分别见 [验证记录](KUN-VALIDATION.md)、[开发进度](KUN-PROGRESS.md)。
