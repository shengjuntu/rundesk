# RunDesk 0.22.0 / Kun 0.3.0

本版推进 K1 的执行内核和可检查状态，使内置文件工具与 MCP 在同一条受控路径执行，并为失控循环提供可验证的停止条件。

## 变更

- 固定四模块、LoopPolicy 和 Provider 接口；模块返回数据，内核掌握状态提交和副作用执行。
- 调用前工具身份与参数校验；有界 2020-12 schema 子集，明确拒绝不支持的约束。
- 每轮工具调用、活动时间、连续工具失败、可选已报告 token 阈值；拒绝和未知结果保持不同语义。
- 预算配置表单、Layers 基础状态检查、跨检查面板保留历史快照选择。
- 模块和预算状态纳入 API/OpenAPI、事件与持久化快照。
- 新增 schema、预算、调用前拒绝和模块快照测试；更新浏览器脚本。

## 升级

保持 Go 1.25.12+ 和现有构建方式：`make build`。同时替换 `rundesk` 与 `kun` 两个可执行文件。worker 协议为 **3**，旧版 worker 不能与新版 RunDesk 混用。Kun 状态 schema 仍为 1，旧记录可检查；新字段为附加字段。本版仍不支持从旧运行检查点恢复执行。

旧配置新增默认预算：每轮 64 次工具派发、900 秒活动时间、3 次连续工具失败；token 阈值默认关闭。可在 Agent 引擎配置修改。MCP schema 比旧版更严格，遇到不支持关键字会明确拒绝运行，需调整服务 schema 或后续扩展验证器，不能绕过校验。

无新生产依赖，无 Node 运行依赖。MCP/模型凭证方式不变。MCP 配置修改仍在下一轮生效；即时撤权尚未实现。
