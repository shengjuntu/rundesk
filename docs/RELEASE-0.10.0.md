# RunDesk 0.10.0 — 应用 Docker 运行环境

应用可以使用自己的镜像和工具环境；通用助手继续使用本机 Codex。数据保存到宿主机，同项目会话复用容器，不为每条历史会话保留新容器。

新增：
- 应用「运行环境」独立页面，创建多个项目环境、复制接入信息、进入对应项目的能力配置。
- Linux 本机 Docker 创建、启动、停止、重建和移除；修改带 revision 检查，运行中任务阻止停止或重建。
- 镜像 ID 固定、CPU/内存/进程限制、只读根目录、限额日志、空闲自动停止。支持普通及 Rootless Docker。
- 挂载独立 CODEX_HOME/HOME 和项目目录；Skills 完整目录、MCP、认证与原生历史按环境保存。
- `docker exec -i` 传输 Codex App Server JSONL。每条连接独立租约，后台失联或连接关闭时清理其子进程，不停止其他会话。
- Docker 退出状态、OOM 和失败详情可见；原生会话可在容器重建后恢复，中断任务不自动重发。
- Docker 轨迹分析使用限定来源会话和事件游标的只读快照，总数据库不进入容器。
- 管理 API 与 OpenAPI 1.8.0；应用凭据不能控制 Docker。

兼容：已有 0.9.2 应用保持本机模式；现有任务、Cron、幂等提交、审批与事件接口继续使用。切换运行方式不会自动搬迁旧会话。详见 [Docker 使用与升级](DOCKER-ENVIRONMENTS.md)。

边界：本版仍为单管理员自托管原型，尚未提供完整多用户/RBAC、镜像构建管理、远程 Docker 和 Windows/macOS Docker 路径映射。挂载不自动清理历史，需自行安排数据保留。Codex 原生沙箱权限不自动放宽。

验证涵盖 Go 竞态测试、监管进程取消、模拟 Docker 和浏览器交互。此执行环境没有 Docker daemon，因此没有完成真实 Docker/模型/MCP 业务组合的验收。附带示例 Dockerfile 和不调用模型的真实 Docker 验收脚本，部署前按文档运行。
