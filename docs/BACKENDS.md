# 后端能力与扩展边界

当前源码包为 RunDesk 0.54.1，后端为独立 Kun 0.17.0（worker 协议 16）与 Codex App Server。RDCA 任务接口保持 `/api/v1`，附加 UHP `/v1` 入口复用同一任务核心。内部准入、运行与停止通过后端注册表分派。

| 能力 | Kun | Codex |
| --- | --- | --- |
| 应用任务、会话、队列、事件、文件 | 支持 | 支持 |
| 工具审批 | Kun 控制与工具策略 | 原生审批协议 |
| 已记录轨迹的查看、步骤、异常、统计 | 支持 | 支持，限原生已暴露证据 |
| 统一调试工作台与模型交互查询 | 原有模型快照与高级面板 | 原生协议事件及实际经过直通代理的 HTTP 字节；有采集边界 |
| 内部单步、条件断点、上下文快照 | 支持 | 不支持 |
| 固定证据的自然语言诊断 | Kun 独立诊断会话 | 原生分析会话 |
| Hybrid 工具回放、Live 分叉 | 支持 | 不支持 |
| 固定案例、规则评分、K4 Skill 验证 | 支持 | 不支持 |
| 本机执行 | 支持 | 支持 |
| RunDesk 托管 Docker 与命名应用运行预设 | 待实现 | 支持 |
| Codex 原生插件 | 不支持 | 配置/来源只读检查；安装与卸载未实现 |
| 模型接入 | 支持工具调用的 Chat Completions | Codex 原生 Provider 配置 |
| 核心编程动作 | 读、写、精确编辑、列目录、grep、find、可选 Bash | 由 Codex 原生工具提供 |

`GET /api/v1/backends` 为管理员能力目录，不启动任何运行时。`GET /api/v1/setup/environment` 检查实例与项目的本机依赖，不测试推理。应用只需调用任务契约；具体模型和后端由管理员配置。

新的运行使用实例当前配置，旧会话保留后端归属；切换后应新建会话。模型、Skills、MCP、权限和执行环境并非彼此等价。Kun 内部 `tool-loop-v1` / `plan-act-v1` 是循环策略，不是第三个后端。

Kun Bash 默认关闭，开启须明确完整宿主访问和独立命令策略。内置文件工具限制、审批、超时、固定评测目录都不构成 OS 沙箱。未提供交互终端、Bash 流式输出、托管 Kun 容器、任意动态模块插件、模型隐藏思维链或业务收益保证。

当前 `RuntimeBackend` 定义 `Info/Prepare/Run/Stop`，通过显式宿主服务接入资源、权限和生命周期。配置、审批、恢复与实验的引擎专属行为仍有专用接口，尚未全部通用化。这是内部模块契约，不是可动态加载的插件 SDK；扩展后端需实现适配器并验证实际能力。

共同任务接口服务应用接入，共同观测接口服务部署调试；研究用的单步、分叉和评测按后端能力开放。UHP 的覆盖也受这些原生能力限制，不能由统一入口推定两个后端等价。见 [UHP 当前边界](UHP.md#当前边界)。
