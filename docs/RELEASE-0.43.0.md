# RunDesk 0.43.0

本版补齐 K4 评测文件相互污染的问题：案例可以声明固定输入文件，并选择独立评测目录。每个来源、独立验证以及动态/快速对照样本均使用新目录；工具与产物检查共同限制在该目录内。预览没有文件操作，执行不会复制原项目，也不会覆盖已有评测目录。

初始化证据绑定案例和固定输入，并成为必需评分项。缺失证据保持未知。批次停止、宿主重启和幂等重试不重置已完成案例；快速路径回退留在同一目录、沿用原账本。

本版仅支持内置文件工具，配置 MCP 时拒绝独立目录模式。快速守卫区分共享工作区与独立目录；隔离候选即使验证通过也只用于评测，不能直接晋升普通应用。既有共享模式继续支持原应用启用流程。

升级 RunDesk 和 Kun 两个程序：Kun 0.15.0、worker v15、fork schema 3。旧定义与报告可读；跨版本预览、检查点和候选需要重新生成/验证。无新路由，OpenAPI 保持 180 paths / 216 operations；无依赖变更。

目录分离不是进程或网络沙箱，不覆盖真实业务效果、统计推断或可选学习型 JEV。使用方法见 [独立评测目录](KUN-FIXTURES.md)，验收见 [验证记录](KUN-VALIDATION.md)，计划对齐见 [开发进度](KUN-PROGRESS.md)。
