# K3-A 离线记录实验（RunDesk 0.31.0）

本版可把 Kun 一个轮次的已保留事件冻结成离线基线，假设工具返回了另一段文本，再逐条查看记录、后续失效范围和分支差异。每次编辑或恢复都新建不可变子分支；原始事件和父分支保持不变。

这是一种 **record_edit 记录编辑回放**：回放按钮只移动阅读位置，不运行模型、工具或 Kun worker，不导入检查点，不恢复文件或回滚外部系统。替代值是未经验证的假设，后续原始回答不能当作该假设下重新生成的答案。Kun 引擎仍为 0.7.0 / 协议 v7；worker 的 `fork=false` 正确表示尚无运行时分叉。

## 使用

1. 管理员打开 Kun 来源会话的“调试检查”，选择一个明确轮次。检查器固定当前宿主事件上界；需要更新时先显式读取最新记录。
2. 点击“创建离线实验基线”。系统保存这个轮次、上界以内、具有明确 runId 的已保留事件。正在暂停或已结束的历史记录均可；创建过程不启动 worker。
3. 在“离线实验”选择一个已完成的工具记录。可编辑成功或失败调用的返回文本；原始 JSON、调用参数、审批及成功/失败状态仍保持原样显示。
4. 填写子分支标题、假设文本和理由，保存子分支。空文本可用于模拟空结果。查看来源谱系、逐条记录、原文分块及相对父分支的差异。
5. 要撤销某个替代值，选择该记录并“恢复原值并新建子分支”。这会建立新的谱系节点，历史分支仍然保留。

主工作台的“离线实验”入口可列出全部来源的实验。基线保存后，即使宿主重启、来源进入新轮次或原会话被删除，也能独立查看、比较和继续编辑实验。

## 事实、假设与失效

| 标记 | 含义 |
| --- | --- |
| 原始记录 / `recorded` | 当前视图中没有被更早的替代值影响的保留记录；不等于记录覆盖了完整运行 |
| 假设结果 / `edited` | 此事件有替代返回文本；原始事件仍可见，未真实执行或重新验证 |
| 后续未验证 / `stale` | 位于最早替代值之后的其他记录，不能作为新假设下的有效推演结果 |

首版没有完整依赖图，因此按宿主事件顺序保守标记：最早编辑点之后的**所有**记录均未重新验证，不限于模型回答。如果后续工具结果也有替代值，它显示为假设结果，同时 `downstreamUnverified=true`。恢复某个替代值后，按剩余替代值重新计算失效范围；全部恢复只还原基线视图，不证明曾进行重新执行。

差异只允许同一基线下的分支，比较分类、后续未验证标志、替代文本、理由及替代值来源分支。它不计算模型质量、成功率或性能收益，也不修改调用状态。一个新分支仍只有一个父节点；不提供合并。

## 固定来源与持久化

来源包含 sessionId、runId、宿主 through、workspaceId 和 instanceId；来源标题仅保存前 120 个 Unicode 字符作为显示摘要。只收录明确归属该轮次的 `kun/*`、`run/input`、`run/state`、`run/steer`；不会把步骤重建器推断的关联当作可编辑事实。`through` 是宿主事件 ID，不能填写 Kun worker sequence。后来的事件、其他轮次和其他会话不进入已有基线。

基线数据先按既有结构化字段规则脱敏，保留 JSON 大整数精度，再存入宿主 SQLite 的 `experiment_bundle`。各分支存入 `experiment`，共享基线，保存有效替代值、单次变更和父节点。基线和内容的 SHA-256 指纹、父指纹用于发现不一致；它们不是数字签名，也不提供对数据库管理员的防篡改保证。

脱敏不保证识别任意自由文本中的凭据。假设文本、理由及标题作为管理员输入原样保存，应按记录数据对待。删除来源会话**不会**删除实验副本；本版尚无实验删除、自动过期、单独导入或导出接口。实验跟随宿主数据库备份；需要清理策略的部署应在启用前考虑这一留存边界。

## API

以下路径均以 `/api/v1` 为前缀，仅管理员可用。应用 key、成员及成员代理入口默认拒绝；诊断 Agent 和公共只读 debug-mcp 工具不包含实验写入功能。两个 POST 使用既有 `Idempotency-Key` 机制，重试复用同一 key 和请求体。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /experiments` | 创建固定基线：`sessionId`、`runId`、`title`，可显式传 `through`；省略时冻结创建时的上界 |
| `GET /experiments` | 列出分支，可按 `sessionId` 筛选，`offset/limit` 分页 |
| `GET /experiments/{eid}` | 分支、计数和从根到当前节点的谱系 |
| `POST /experiments/{eid}/branches` | 新建子分支：`title`、`expectedParentHash`、`change` |
| `GET /experiments/{eid}/events` | 固定事件元数据、假设及失效标记，`offset/limit` 分页 |
| `GET /experiments/{eid}/events/{eventId}` | 原始脱敏 JSON 的 Unicode 字符分块和当前记录视图 |
| `GET /experiments/{eid}/diff` | 与父分支比较；根默认与自身比较，可用 `against` 选择同根分支 |

`change` 示例：

```json
{
  "eventId": 9,
  "operation": "replace",
  "text": "假设工具没有找到材料",
  "reason": "检查后续结论对这份材料的依赖"
}
```

`restore` 要求该事件已有继承的替代值，且不得附带非空 text。不接受 `live`、目标会话、模型配置或执行控制等附加字段。没有 `/execute` 路由。分支详情返回的 contentHash 用作新建子分支的 expectedParentHash。

## 边界

| 项目 | 上限 |
| --- | --- |
| 一份基线 | 2,000 条事件；原始总量 16 MiB；单事件 4 MiB；脱敏后的包 20 MiB |
| 基线读取 | 10 秒上下文超时；先测量记录大小再读取载荷，超限拒绝，不静默截断 |
| 分支 | 根深度 0，最大深度 32；最多 32 个有效替代值 |
| 编辑内容 | 标题 1–120 字符，理由 1–2,000 字符，替代文本 0–16,000 字符 |
| 列表 / 事件页 | 默认 20 条，最多 50 条 |
| 差异页 | 默认及最多 16 条 |
| 原文分块 | 默认 4,000，最多 16,000 个 Unicode 字符；JSON 响应最多 4 MiB |

离线记录实验首版仅 Kun 来源，不支持 Codex 记录编辑。当前 0.33 另有 [K3-B Hybrid](KUN-FORKS.md) 和 [K3-C Plan-Act / 内置组合 / Harness 对照](KUN-HARNESS.md)，独立于此处的记录编辑。Live、运行中换模块以及 K4 候选生成/验证/IR 尚未实现。验证见 [KUN-VALIDATION.md](KUN-VALIDATION.md)，完成度见 [KUN-PROGRESS.md](KUN-PROGRESS.md)。
