# 按开发计划核对完成度（RunDesk 0.29.0 / Kun 0.7）

依据 KUN-DESIGN-v0.2.md 第 15 节逐阶段核对。截至 2026-10-06，不按文件数或界面数量推算百分比；“已有实现”与“完整验收”分开。

| 阶段 | 已有实现与证据 | 尚未完成 / 未验收 |
| --- | --- | --- |
| K0 进程与源码边界 | 同仓双命令；独立 worker、协议握手、目录锁、事件补取、退出处理；UPSTREAM 逐文件来源与许可证；全量 Go 回归；统一只读 DebugService 与固定会话 MCP | 跨后端完整 runtime/控制抽象仍不完整；生产长时间/慢消费者压力验收未完成 |
| K1 最小原生运行与检查 | 模型→工具→回复，MCP 审批，动作账本、预算、参数校验；独立执行库；Network/Elements/基础 Performance；实际输入可追溯 | 真实模型/MCP 和业务端到端验收未执行；高级压缩/记忆等能力超出当前实现 |
| K2 基本干预与恢复 | 暂停/单步/steer/停止；四边界条件断点；Console；控制 revision/幂等；安全检查点显式续跑；真实进程终止/宿主重启测试；已有精确证据、上下文树、快照差异；已有结构化控制/用量/MCP/四模块面板；统一只读服务与 MCP 已有；已有 Codex/Kun 轮次、步骤、异常、统计重建及只读检查；本版增加 Kun 独立自然语言诊断、固定证据查询、可审核建议和追问；本地浏览器验收见验证记录 | 真实 Codex/模型/MCP 与生产环境验收待完成；Codex 内部单步/条件断点/完整上下文快照、诊断器跨实例选择、提案应用与当前状态校验整合、更多条件信号、高级上下文来源图尚未实现 |
| K3 组合与分叉 | 固定四模块接口、版本化状态、第一种 tool-loop-v1 和基础 Layers 是前置设施 | 第二种 LoopPolicy、可配置组合、Harness 对比、Deterministic/Live/Hybrid、谱系、历史分叉、完整离线实验调试未实现；离线宿主历史查看已具备 |
| K4 优化实验 | 设计文件记录边界 | Skill 候选生成、快速路径 IR、守卫/去优化、决策模型及独立验证集均未实现 |

0.29.0 的实际增量集中在 K2 独立诊断会话和有证据的建议，不将固定模块或快照差异计作 K3 分叉完成。完整验证命令与未执行项目见 [KUN-VALIDATION.md](KUN-VALIDATION.md)。

统一只读契约与接入已补齐这一批范围，见 [DEBUG-SERVICE.md](DEBUG-SERVICE.md)。本地协议桩浏览器验证不代替真实服务。Kun 诊断已复用其模型/工具循环，Codex 沿用已有原生分析会话；后端由来源固定，尚不能任选诊断器。后续优先开展真实 Codex/模型/MCP 环境的 K2 验收，再将建议与当前状态下的控制预览整合。Codex 内部能力受其可暴露协议限制，不因共用接口而视为已实现；分叉/组合应在可追溯状态和副作用边界稳定后实施。
