# 按开发计划核对完成度（RunDesk 0.25.0 / Kun 0.6）

依据 KUN-DESIGN-v0.2.md 第 15 节逐阶段核对。截至 2026-10-05，不按文件数或界面数量推算百分比；“已有实现”与“完整验收”分开。

| 阶段 | 已有实现与证据 | 尚未完成 / 未验收 |
| --- | --- | --- |
| K0 进程与源码边界 | 同仓双命令；独立 worker、协议握手、目录锁、事件补取、退出处理；UPSTREAM 逐文件来源与许可证；全量 Go 回归 | 跨后端统一 runtime/DebugService 抽象仍不完整；生产长时间/慢消费者压力验收未完成 |
| K1 最小原生运行与检查 | 模型→工具→回复，MCP 审批，动作账本、预算、参数校验；独立执行库；Network/Elements/基础 Performance；实际输入可追溯 | 真实模型/MCP 和业务端到端验收未执行；高级压缩/记忆等能力超出当前实现 |
| K2 基本干预与恢复 | 暂停/单步/steer/停止；四边界条件断点；Console；控制 revision/幂等；安全检查点显式续跑；真实进程终止/宿主重启测试；本版补精确证据、上下文树、快照差异 | 浏览器及真实服务验收待完成；统一跨后端调试服务/MCP 工具、自然语言诊断、更多条件信号和其余面板结构化尚未实现 |
| K3 组合与分叉 | 固定四模块接口、版本化状态、第一种 tool-loop-v1 和基础 Layers 是前置设施 | 第二种 LoopPolicy、可配置组合、Harness 对比、Deterministic/Live/Hybrid、谱系、历史分叉、离线调试未实现 |
| K4 优化实验 | 设计文件记录边界 | Skill 候选生成、快速路径 IR、守卫/去优化、决策模型及独立验证集均未实现 |

0.25.0 的实际增量集中在 K1 检查与 K2 调试，不将固定模块或快照差异计作 K3 分叉完成。完整验证命令与未执行项目见 [KUN-VALIDATION.md](KUN-VALIDATION.md)。

下一批优先补 Sources/Performance/Application/Layers 的结构化检查与统一证据入口，再进行具备浏览器和真实服务环境的 K2 验收；分叉/组合应在可追溯状态和副作用边界稳定后实施。
