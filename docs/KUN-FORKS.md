# Kun 分叉、工具结果假设与对照

先固定来源与安全点，再选择 Hybrid 或 Live 分支；工具结果假设和来源／分支对照沿用这一基线。它们是保留的研究 API 与已有记录查看能力；旧专题中的创建按钮不代表当前日常导航。下文保留执行、副作用、证据和权限边界。

<a id="runtime-forks"></a>

## 建立 Hybrid 或 Live 分支

> 可配合 [同基线对照](KUN-FORKS.md#branch-comparison) 与 [工具结果假设](KUN-FORKS.md#tool-hypotheses)，假设保留原录制。


版本和格式兼容规则见 [Kun 接口](KUN-SEPARATION.md)。管理员可从**最近已停止的普通 Kun 运行**中选择安全边界，生成绑定模式的固定预览，再启动独立执行分支。已有普通运行安全点组合切换；任意模块迁移和统计推断尚未完成；K4 基础闭环见 [KUN-K4.md](KUN-K4.md)。案例与快速路径运行不作为可恢复/可分叉来源。

<a id="forks-1"></a>

### 三种实验的区别

| 方式 | 模型与工具 | 数据边界 |
| --- | --- | --- |
| [离线记录实验](KUN-EXPERIMENTS.md) | 不调用模型或工具，只编辑观察记录 | 不提供可执行状态；后续记录为未验证 |
| Hybrid | 模型重新调用；工具仅严格录制回放，未命中停止 | 新执行库与私有空工作目录；不执行真实文件工具或连接 MCP |
| Live | 模型和工具均可真实执行；使用当前项目文件和当前 MCP 服务 | 新执行库，**共享当前项目工作目录**；不复制、隔离或回滚文件和外部世界 |

来源执行记录不会因分支改变，但 Live 可以修改来源项目中的文件、产物和外部服务。来源在选中边界之后执行过的动作可能再次执行；历史观测不代表当前世界。独立会话不等于文件沙箱，也没有跨分支“恰好一次”保证。

<a id="forks-2"></a>

### 操作

1. 选择已停止的普通 Kun 会话，点击顶部 **Kun 分叉**，或轨迹 → Kun 高级调试 → Sources 的分叉入口。
2. 选择安全边界和模式（默认为 Hybrid），填写标题及可选补充指令，点击 **生成固定预览**。
3. 核对来源 run、序号、截止游标、继承预算和内容指纹。Live 额外显示实际工作区、内置写文件权限、审批策略、MCP 工具数量及待处理工具参数摘要。
4. Live 需要勾选 **确认 Live 真实执行**，随后才能启动。首次启动创建独立会话；再次启动同一预览返回同一目标。重新打开预览需要重新确认，改变模式、边界、标题或指令会使旧预览失效。

预览不发起模型、MCP 或文件工具调用。本地技能会被读取以校验内容；只读检查 worker 可能被重新启动，并按既有恢复规则把中断的活跃状态记为 interrupted。Live 启动才重新连接 MCP，模型/工具调用进入真实执行路径；选中最终回复后的边界且无补充指令时，可能直接结束而没有新增模型/工具调用。

**已有待处理工具保留原参数并先完成该批工具处理；补充指令在下一次模型请求前加入，不能改写这些待处理动作。** 不支持修改已有消息、工具参数、配置或录制文本。Live 的固定预览应重点检查这些动作；参数摘要是有界且可能截断的，不是全部执行上下文。

<a id="forks-3"></a>

### 共同约束

| 项目 | 当前行为 |
| --- | --- |
| 来源 | 普通 Kun 会话最近停止的运行；排队/运行中、诊断、Codex 和嵌套分叉拒绝 |
| 安全点 | 当前引擎及 Harness/模块版本兼容，目录就绪；模型前后、工具前后或待审批边界；无派发中/未知结果动作、无待应用控制 |
| 当前来源未知结果 | 只要当前账本有 dispatched/outcome_unknown，整个来源拒绝导出，不能选择更早边界绕过 |
| 来源一致性 | 校验 run、worker epoch、state revision、sequence 和精确 through；来源改变需重新读取 |
| 固定模式 | 模式包含在 bundle 指纹与来源绑定中；不能把 Hybrid 预览改为 Live 启动 |
| 配置 | 使用相同原始配置及选中快照的有效 Harness（含 runtimeHarness）；实例、项目、权限、技能或 MCP 配置变化拒绝。模型 key 值在启动时读取 |
| 上下文与预算 | 保留快照上下文、已完成计划、步骤、token、工具次数、活动/等待时间与失败计数；不会恢复满额 |
| 计划 | Plan-Act 从已完成计划继续，不重新规划；选择规划前边界则执行规划。保留来源已明确切换的组合；分支本身不能再切换，也不能借分叉请求更换组合 |
| 一次运行 | 一份预览只绑定一个目标 session/run；响应丢失、新 HTTP Key、宿主重启都不会再建一次目标 |
| 继续与中断 | 禁止普通新轮次和检查点续跑；中断后另建预览，并自行核对外部实际结果 |
| 删除 | 目标删除和预览删除标记在同一事务，旧预览不能复活目标；未启动预览可在来源删除后使用，但当前项目和环境仍须有效 |

<a id="forks-4"></a>

### Live 执行检查

启动没有 `confirmLive=true` 时，宿主在创建目标前拒绝。确认并不是跳过工具审批：宿主重新读取 Skills、MCP 配置及其已解析凭据，核对规范化项目路径、配置/上下文 revision 和摘要；真正启动 worker 时再检查一次。MCP 凭据改变也会阻止该预览执行，不把凭据保存到分叉包。worker 在连接前检查继承预算；预算已耗尽时不发起新增模型、MCP 连接或工具调用。

worker 清空历史的一次性审批决定和原 MCP 连接状态，重新连接当前服务，并在派发模型/工具前核对完整目录指纹。目录漂移导致停止，不静默接受新 schema 或工具。当前工具配置为 prompt 时会重新询问；当前配置允许自动执行时按该权限执行；禁用的工具不能通过历史审批放行。连接 MCP 本身不是工具审批，也不提供服务进程沙箱。

工具事件标记 `executionMode=live`。Application、Sources、Performance、Harness 对照及会话横幅区分真实执行和回放；Performance 分开显示继承用量与本分支新增派发。内置 `allowWrite` 约束内置文件工具，不代表 MCP 工具没有写入能力。

<a id="forks-5"></a>

### Hybrid 严格回放

Hybrid 不发现或连接 MCP，不执行文件工具，不请求真实执行审批。工具网关另有禁止真实派发的保护。匹配要求同时满足：引擎/环境/目录指纹、工具身份和 schema、规范化参数、下一条录制位置；不向后搜索，也不只按名字匹配。未命中以 `replay_miss` 停止，没有 Live 回退。

参数规范化忽略对象键次序与空白，保留 JSON 大整数精度，拒绝重复键、非对象和尾随内容；`1` 与 `1.0` 保守视为不同。原录制只接受已保存的 succeeded/failed 执行结果，不把审批拒绝、参数拒绝或未知结果当作录制。回放事件含来源序号、位置、原状态、bundleHash 和 `executed=false`。工具预算照常消耗，但不是外部调用；分支可以提前结束并留下未使用录制。

<a id="forks-6"></a>

### 数据和接口

分叉包从 worker 私有执行状态导出，不从宿主脱敏事件重建，也不导入离线记录实验的假设。包含历史上下文和工具文本，应按原执行数据库保护；模型/MCP 凭据不另存入包，环境清单只保存摘要。HTTP 不收发可执行 bundle。

Live 公开详情只增加工作区、权限及待处理动作摘要；参数中的常见凭据字段脱敏，每项最多 2048 字符并标明截断。任意敏感自由文本无法保证自动识别。列表省略 instruction 和 live 动作详情，不包含历史模型/工具正文。

固定包上限 4 MiB，选中快照 2 MiB。Hybrid 最多 128 条后续工具结果，原始事件合计 2 MiB、单条 1 MiB；参数规范化限制 256 KiB、64 层。Live 不携带录制带，不受后续 128 条结果限制，仍受包和快照上限约束。预览与来源边界每页最多 50 条；暂无预览删除、过期、导入或压缩接口。

| 管理员 API | 行为 |
| --- | --- |
| `GET /api/v1/kun-forks/sources/{sid}?offset=0&limit=50` | 固定来源游标及安全边界；创建时用 items 中的正 sequence |
| `POST /api/v1/kun-forks` | `{sessionId, selection, title, instruction?, mode?}`；mode 为 hybrid/live，省略为 hybrid |
| `GET /api/v1/kun-forks?offset=0&limit=20` | 预览列表，省略指令和 Live 动作详情 |
| `GET /api/v1/kun-forks/{fid}` | 完整公开预览 |
| `POST /api/v1/kun-forks/{fid}/start` | `{expectedHash, confirmLive?}`；Live 必须 confirmLive=true；启动/返回固定目标 |

上述两个 POST 要求 `Idempotency-Key`。上述操作仅管理员开放，应用 key、成员 runner/viewer 及成员代理入口拒绝；不接受客户端注入 bundle 或新目标。启动仍受宿主并发、进程容量和执行环境检查；HTTP 接收成功不代表执行成功，应查看目标状态。hello 为 `fork=true, forkHybrid=true, forkLive=true, forkHypothesis=true`。

另有管理员录制摘要 GET 和假设子预览 POST；后者也要求 Idempotency-Key。假设详情显示用户填写的完整 output/reason，列表省略这两项，具体边界与证据见 [工具结果假设](#tool-hypotheses)。

同基线分支可使用 [固定规则评分](KUN-EVALUATION.md#branch-scoring)。评分不启动模型或工具。

### 版本和验收

配套构建 RunDesk 与 Kun，结束旧 worker 后替换。执行预览与检查点受引擎和格式版本守卫限制；0.16.0 到 0.17.0 的兼容范围见 [Kun 接口](KUN-SEPARATION.md)，部署操作见 [升级](UPGRADING.md)。

本地内核、实际 worker/HTTP fixture、权限/审批、专项 race 和 Node DOM 交互通过。真实浏览器、真实 Codex/远程模型/MCP、Windows 实机和生产压力未验收；不要把本地桩测试等同真实业务效果。详见 [验证记录](VALIDATION.md) 与 [开发进度](STATUS.md)。

<a id="tool-hypotheses"></a>

## 工具结果假设与 Hybrid 重算

管理员可以从当前版本的固定 Hybrid 预览中选择一条工具结果，填写完整替换文本，保存独立假设预览，再启动模型重算。原录制不改写。假设与原录制回放、真实工具执行分别标记；这是受控反事实实验，不是对外部世界的验证或质量评分。

运行版本与格式兼容规则见 [Kun 接口](KUN-SEPARATION.md)。旧执行记录和分支对照可只读查看；检查点和预览必须通过当前引擎守卫，不能把不兼容预览转换为新假设。需要时重新完成普通运行并生成 Hybrid 预览。

<a id="hypotheses-1"></a>

### 操作

1. 打开一个**尚未修改工具结果的 Hybrid 固定预览**。父分支不需要先启动。
2. 在“修改工具结果 → Hybrid 重算”点击“读取可替换结果”。显示所选安全点之后的录制顺序、工具、原状态、完整输出指纹和有界节选。
3. 选择一条结果，填写标题、替换理由和**完整新输出**。允许明确的空字符串；不会把截断或脱敏的原文节选自动填成替换值。切换结果会清空尚未保存的替换文本。
4. 点击“保存假设固定预览”。此步不创建执行会话，不启动 worker、模型、工具或外部连接。新预览继承父级补充指令、原始执行快照和预算。
5. 核对新预览中的替换全文、理由、父预览及指纹，再点击“启动或打开 Hybrid 分支”。这一步会调用模型并消耗用量。每份预览只运行一次；重复提交返回同一目标。
6. 读取“来源与分支对照”，可选择父预览对应的执行结果作左侧。查看“原录制回放”“假设替换”“真实派发”计数及假设使用状态；“查看假设结果事件”定位实际使用证据。

每个子预览只替换一个结果；如需另一个假设，从未修改的父预览重新创建。不支持 Live、叠加替换、修改工具参数/身份/成功失败状态、执行嵌套分叉，或导入离线记录实验的脱敏文本。完整依赖图、多结果编辑和实验清理仍未实现；固定规则评分由 [评测入口](KUN-EVALUATION.md#branch-scoring) 提供。

<a id="hypotheses-2"></a>

### 执行与证据

私有 bundle 保留原始 `records`，新增 `hypothesis` 叠加项。它绑定父预览 ID/哈希、父 bundle 哈希、零起始录制位置、来源序号、完整原录制指纹、原/新输出指纹、理由和替换全文。子 bundle、公开预览和固定目标都有新身份。所有哈希受完整预览校验保护；worker 在执行前另行验证叠加项和原录制绑定。

`recordHash` 是原 ReplayRecord 的标准 JSON 编码 SHA-256；`originalOutputHash` 和 `outputHash` 是各自完整 UTF-8 文本字节的 SHA-256。父 bundle 去掉叠加项后必须恢复原 bundle 指纹。替换值与原文完全相同时拒绝保存，避免把未改变的输出误标成实验变化。

Hybrid 仍只匹配**下一条**录制的工具身份、schema、规范化参数、环境和目录，不向后搜索，不进行真实工具派发，不连接 MCP，不读写项目文件。未命中以 `replay_miss` 停止。工具的 `status`/`isError` 保留，因此把失败文本改写成成功措辞不会把工具变为成功。

运行系统说明明确人工假设的位置及其未验证性质。只有执行到选定位置且匹配成功时才替换模型收到的 tool 文本；假设并不保证一定被使用。`kun/tool.completed` 仍为 `status=replayed`，`replay.mode=hypothetical`、`executed=false`，附来源位置、原/新输出和假设指纹。其他结果保持 `mode=recorded`。两者均消耗继承预算下的工具额度。

| 对照状态 | 含义 |
| --- | --- |
| `applied` | 所选固定宿主范围内已有匹配假设指纹的完成事件，返回事件 ID；即使后续日志尚未完整，也能证明这次使用 |
| `not_reached` | 启动来源、继承预算及连续结束日志均完整，范围内没有使用此假设 |
| `unknown` | 未运行、日志缺失/未同步完整或尚未结束，不能断言是否最终使用 |

固定上界为零时始终是未记录；新事件须显式刷新。日志删除不会被视为“假设未使用”。假设输出和理由不进入对照摘要；模型回复仍按既有有界回复规则显示，可能包含模型引用的文本。

<a id="hypotheses-3"></a>

### API、边界与保留

| 管理员 API | 作用 |
| --- | --- |
| `GET /api/v1/kun-forks/recordings/{fid}` | 返回 `previewId/previewHash/items`；每项含位置、来源序号、工具、原状态、recordHash/outputHash、字节数、节选及脱敏/截断标记 |
| `POST /api/v1/kun-forks/{fid}/hypotheses` | 请求 `expectedHash, position, recordHash, output, reason, title`；要求 `Idempotency-Key`，创建固定子预览 |
| `GET /api/v1/kun-forks/{fid}` | 子预览详情包含用户填写的完整假设文本和理由；列表省略这两项 |
| `POST /api/v1/kun-forks/{fid}/start` | 沿用 `expectedHash` 与单目标幂等执行；假设只能 Hybrid |
| `GET /api/v1/kun-forks/comparisons/{fid}` | 新增 `tools[].hypothetical` 与 `hypothesis` 指纹/状态/证据摘要；`replayed` 仅计原录制回放 |

应用 key、成员 runner/viewer 和成员代理均拒绝。HTTP 不接受可执行 bundle，离线记录实验的宿主脱敏事件不能替代权威私有录制。父预览和原始数据保留；来源删除、父目标删除或宿主重启不改变已保存的子预览。启动仍核对当前配置、工作区存在性和执行容量；目标删除后该子预览不重建。

最多 128 个录制结果；展示每项最多 2048 Unicode 字符。可解析 JSON 的常见凭据字段脱敏，任意自由文本无法保证自动识别。摘要不含完整消息历史、工具参数或执行包。新输出最多 **64 KiB UTF-8 字节**，理由 1–1000 字符，标题沿用 120 字符限制；空 output 必须显式传 `""`，缺省/null 拒绝。添加叠加项后的整个 bundle 仍不能超过 4 MiB。

本地内核、真实 worker、HTTP、权限与 Node 交互验证见 [VALIDATION.md](VALIDATION.md)。真实浏览器布局、真实远程服务、Windows 实机和生产验收未完成。

<a id="branch-comparison"></a>

## 固定范围内比较来源与分支

从同一安全点比较来源后续执行与 Hybrid/Live 分支，也可比较两个同源分支。只读宿主数据库，不启动或恢复 worker、不调用模型/MCP、不读写项目文件。协议及格式兼容范围见 [Kun 接口](KUN-SEPARATION.md)。对照仍可读取原版本固定预览与保留日志，不启动旧执行状态。

提供 comparison `hash` 与 `baseline.hash`，并接入 [固定规则评分](KUN-EVALUATION.md#branch-scoring)。只读对照本身仍不评分；另行保存规则和固定评分报告，不启动执行。

<a id="comparison-1"></a>

### 使用

1. 在“Kun 分叉”打开已保存的预览，在“来源与分支对照”点击“读取最新对照”。无需再次启动分支；未启动、已删除或日志缺失时显示未记录/未知。
2. 默认左侧为来源选中安全点之后、预览来源截止以内的执行，右侧为这个预览的分支新增执行。继承模型次数、工具预算和已报告 token 单列。
3. “加载同源分支”按 50 个预览分页扫描，显示同一来源会话、轮次、安全点和截止的其他预览。若还有后续页，可继续加载。选择后重新读取；服务端另校验完整基线状态、环境和工具目录摘要，拒绝不一致的预览。
4. “重读固定范围”保留两侧宿主事件上界，包括 0；“读取最新对照”显式接纳新的已同步日志。新事件不会自动替换当前结果。
5. 回复最多预览 2048 个 Unicode 字符，显示完整字符数、JSON 字符串 SHA-256 指纹及原始宿主事件入口。点击证据沿用固定轮次和宿主范围。

### 数值的含义

| 项目 | 计算依据与边界 |
| --- | --- |
| 模型次数 | 所选范围中的 model.started，包含规划；不把继承次数当作分支新增调用 |
| 规划次数 | purpose=plan；规划文字不作为新增回复 |
| 已报告 token | model.completed 的有效 total_tokens，或同时存在的 prompt_tokens+completion_tokens；缺失、无效或调用没有完成均标记不完整 |
| 活动/等待时间 | 完整结束事件预算减去安全点的继承预算；字段缺失、记录不完整或数值倒退时为未知；不使用浏览器计时器 |
| 工具派发 | tool.started 的真实派发记录，不包含 Hybrid 录制回放；派发不等于副作用成功 |
| 原录制回放 | tool.completed 的 mode=recorded、executed=false；不含人工假设 |
| 假设替换 | mode=hypothetical、executed=false；核对固定替换指纹，单独计数并链接使用事件 |
| 失败结果 | 真实失败或录制的失败结果，须结合当前侧执行模式理解 |
| 拒绝 | 审批拒绝或参数校验拒绝，没有据此推断真实调用 |
| 未见结果 | 已派发但该固定范围没有完成记录；可能仍在运行或结果未知 |
| 新增回复 | 最后一条非规划、无工具调用的已记录模型文本；运行结束和文本出现不代表业务任务验收通过 |

每侧逐条检查 worker 序号连续性、会话/轮次/事件身份及结束记录；分支核对启动记录的来源和继承预算。来源还必须覆盖到预览的固定 worker 截止。不完整时保留“已记录”的计数，但不计算完整运行差值。差值为右侧减左侧；token 和时间各自还要求有效测量值。

两侧保留不同宿主游标，不承诺并发运行在同一个墙钟时刻冻结。宿主尚未同步的事件不会被推测补齐；显式刷新后才会进入对照。宿主重启、worker 回收后，只要预览与宿主记录仍保留，就能读取。删除来源/目标可能删除对应日志；本功能不额外创建永久日志副本，也不复活已删除会话。

### API 与权限

`GET /api/v1/kun-forks/comparisons/{fid}`（旧 `/api` 别名相同），仅管理员。应用 key、成员 runner/viewer 和成员代理均拒绝。该接口不加入只读 Debug MCP 目录。

| 参数 | 含义 |
| --- | --- |
| against | 可选，同一基线的另一预览 ID；省略/空串为来源运行；不可指向自己 |
| leftThrough | 可选，左侧宿主事件 ID 上界，非负整数；省略时固定当前最大值 |
| rightThrough | 同上，右侧独立上界；0 表示固定空范围，不能在客户端丢弃 |

未知/重复参数拒绝。不同基线、记录身份冲突或超出当前保留范围的游标返回 409。每侧限制 4096 事件、32 MiB 总载荷、8 MiB 单事件；先测大小再读取，不静默截断。查询期限 10 秒，完整 HTTP 响应限制 4 MiB，超限返回 413。

响应只含明确选出的摘要字段，不返回私有分叉包、系统提示词、完整消息历史、工具参数或工具输出。回复文本沿用宿主脱敏记录；任意自由文本中的敏感信息无法保证自动识别。API 的 through 是宿主事件 ID，baseline.sequence/through 是来源 worker 序号，不可混用。

假设分支额外显示父预览、位置/指纹和 applied/not_reached/unknown，只有完整连续结束且未见使用才标记 not_reached。具体语义见 [工具结果假设](#tool-hypotheses)。

### 当前不包括

这不是同条件评测基准：分支说明、补充指令、不同模型输出及外部世界变化都可能影响结果。Live 使用当时的当前项目/服务；Hybrid 回放历史结果。界面明确标出模式、指令或 Harness 不同，缺失不按零，对照本身没有质量分数、实际账单、节省比例或优化成功结论；独立的单独规则得分只描述明确文本条件的通过率。

暂不支持任意会话对照、改变分支固定 Harness、产物文件内容对比、自动实验调度、此对照接口直接提供独立验证集评分、离线脱敏记录假设导入 Hybrid（支持直接从权威录制创建单条替换）；K4 在单独的 [Skill 工作台](KUN-K4.md) 实现。当前能力和验证见 [状态](STATUS.md)、[验证记录](VALIDATION.md)。
