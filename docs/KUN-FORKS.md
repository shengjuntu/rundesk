# K3-B：安全运行时分叉与 Hybrid（0.32.0 首批）

需要 RunDesk 0.32.0、Kun 0.8.0、worker 协议 v8。管理员可从**最近已停止的普通 Kun 运行**中选择安全边界，生成固定预览，再启动独立执行分支。后续模型请求重新调用服务，工具只使用匹配的录制结果；未命中以 `replay_miss` 停止，没有真实执行回退。

这不是 K3 全部完成。Live、第二种 LoopPolicy、可配置模块组合、Harness 对比和 K4 尚未实现。本版核心/HTTP/Node 交互验证通过；真实浏览器受执行环境套接字限制未完成，详见 [验证记录](KUN-VALIDATION.md)。

## 操作

1. 选择已停止的普通 Kun 会话，点击顶部 **Hybrid 分叉**，或 DevTools → Sources → **预览 Hybrid 分叉**。
2. 选择一个安全边界，填写标题及可选补充指令，点击 **生成固定预览**。
3. 检查来源 run、worker 序号和截止游标、待处理工具、录制数量、继承预算、上下文变化及内容指纹。
4. 点击 **启动或打开 Hybrid 分支**。首次启动创建独立会话；后续点击返回同一会话。会话横幅、Network 工具证据、Sources、Performance 和 MCP 面板标明回放模式。

预览不发起模型或工具调用。检查时可能重新启动只读检查用 worker，并按既有恢复规则把中断的活跃状态记为 interrupted；本地技能文件会被重新读取以校验内容。启动后才可能产生新增模型用量。若选中最终回答之后的边界且没有补充指令，分支可能直接结束，新增模型调用为零。

标题、补充指令或边界变化需要重新生成预览。补充指令先排队：若检查点有待处理工具，先完整回放该批结果，再在下一次模型请求前加入用户消息，保持工具消息协议顺序。系统会固定加入 Hybrid 模拟说明；不支持修改已有消息、工具参数、配置或录制返回文本。

## 运行与副作用边界

| 项目 | 本版行为 |
| --- | --- |
| 来源 | 普通 Kun 会话最近停止的运行；排队/运行中、诊断会话、Codex、Hybrid 嵌套分叉拒绝 |
| 安全点 | 兼容当前引擎与模块版本、目录已就绪；模型前后、工具前后、待审批边界；无派发中/结果未知动作和待应用控制 |
| 当前来源未知结果 | 只要当前动作账本仍有 dispatched/outcome_unknown，整个来源拒绝导出，不退到更早边界绕过 |
| 来源一致性 | 校验 run、worker epoch、state revision、sequence、精确 through；状态变化须重新读取 |
| 隔离 | 新 session/run、独立 SQLite 与私有空执行目录；不复制项目文件、不改来源、不消费来源恢复检查点 |
| 模型 | 使用当前配置的模型服务和认证，重新发送分支上下文；这会产生真实模型调用/用量 |
| 工具 | 冻结原目录；不发现/连接 MCP，不执行文件工具，不请求或复用真实执行审批；工具网关另有 Hybrid 拒绝保护 |
| 回放匹配 | 引擎/环境清单/目录指纹、工具身份与 schema、规范化参数、下一条录制位置同时匹配；不向后搜索、不只按名字匹配 |
| 参数规范化 | 忽略对象键次序和空白，保留 JSON 大整数精度；拒绝重复键、非对象和尾随内容；`1` 与 `1.0` 保守视为不同 |
| 录制结果 | 仅已保存的 succeeded/failed；拒绝审批拒绝、参数拒绝、未知结果等非执行录制；本次事件标为 replayed，含来源序号、位置、原状态、bundleHash、executed=false |
| 预算 | 保留所选快照的模型步骤、token、工具次数、活动/等待时间和失败计数；后续模型与回放步骤继续消耗剩余额度，不恢复满额 |
| 预算显示 | Performance 分开显示继承与新增模型/token，以及本分支回放数；工具预算消耗不代表外部工具调用 |
| 中断与重试 | 一份预览只允许一次运行；响应丢失/新 HTTP Key/宿主重启均返回同一目标；禁止普通新轮次与检查点续跑；中断后另建预览 |
| 删除 | 删除目标会话与保存删除标记为同一事务，旧预览无法重新创建它；未启动预览可在来源删除后使用 |
| 配置漂移 | 生成/启动预览时核验实例、项目、权限、技能和 MCP 配置；启动前再次核验有效模型配置；变化拒绝。模型 key 值在启动时读取 |

回放可以提前结束并留下未使用录制；游标显示实际使用数量。新增模型沿不同路径选择工具时，允许的结果是匹配回放或停止，不能从模拟成功推断当前外部世界。原项目文件和远端副作用没有被撤销，也没有“恰好一次”外部执行保证。

## 数据和接口

执行包从 worker 的执行状态和记录导出，不从宿主已脱敏的调试事件重建，也不导入 K3-A 假设。私有包包含历史上下文和工具文本，应按原执行数据库的敏感数据保护；HTTP 只返回预览元数据及用户输入的补充指令，不暴露可执行 bundle。模型/MCP 凭据不另存入包；清单保存摘要。

固定包上限 4 MiB，所选快照 2 MiB；最多 128 条工具结果，原始事件合计 2 MiB、单条 1 MiB。参数规范化限制 256 KiB、64 层。预览列表每页最多 50 条；来源边界每页最多 50 条。首批没有预览删除、过期、导入或压缩管理接口。

| 管理员 API | 行为 |
| --- | --- |
| `GET /api/v1/kun-forks/sources/{sid}?offset=0&limit=50` | 返回固定来源游标及安全边界；游标 sequence 初始为 0，创建时用 items 中的正序号 |
| `POST /api/v1/kun-forks` | `{sessionId, selection, title, instruction?}`；创建不可变预览，要求 Idempotency-Key |
| `GET /api/v1/kun-forks?offset=0&limit=20` | 列表省略补充指令，无私有上下文 |
| `GET /api/v1/kun-forks/{fid}` | 读取完整公开预览 |
| `POST /api/v1/kun-forks/{fid}/start` | `{expectedHash}`；明确启动/返回固定目标，要求 Idempotency-Key |

这 5 个操作均仅管理员开放，应用 key、成员 runner/viewer 及成员代理入口默认拒绝。POST 不接受客户端注入 `live`、bundle 或新目标。启动沿用宿主并发、进程容量和执行环境检查；HTTP 接收成功并不等于分支完成，应查看会话状态。Worker 增加 `fork.points`、`fork.export` 与 `start.fork`；hello 为 `fork=true, forkHybrid=true, forkLive=false`。

## 版本边界

升级时同时更新两个命令并结束旧 worker。0.7 的原执行记录可继续查看，但不能跨引擎版本恢复或分叉；先用 0.8 完成新的普通 Kun 运行。本版不支持任意历史轮次、Hybrid 再分叉、真实文件快照、Live、录制结果注入、模块切换或生产长时间压力验收。

K3-A 的离线记录编辑及谱系仍可使用，见 [KUN-EXPERIMENTS.md](KUN-EXPERIMENTS.md)。它只修改观察记录，不提供可执行状态。
