# 任务过程与轨迹分析 · 0.8.0

轨迹围绕每次提问展开：问题是什么，实际尝试了哪些步骤，工具返回了什么，助手给出了什么回复。执行完成与业务目标是否实现分别呈现。

## 界面

1. 在已有会话点击「轨迹」。左侧选择问题轮次，刷新后保留所选轮次、步骤与筛选条件。
2. 中间按发生顺序显示实际记录的工具、公开摘要、审批、上下文与状态。可筛选工具或需关注步骤、搜索记录；每页最多 60 步，所有页仍可查询和导出。
3. 点开步骤，查看输入、输出、错误及时间依据；展开原始事件，按事件编号读取或下载完整记录。大文本提供明确截断提示。
4. 「本轮回复」展示助手实际输出。优先使用明确标为 final_answer 的回复；无阶段标记时说明其为最新助手回复；仅有 commentary 不冒充最终回复。
5. 「工具返回的链接」只收集工具输出中的网址，不把输入网址当作已访问来源，也不自动声称链接内容已经核实。会话文件单列，不猜测它属于哪一轮。

示例：使用技能查询某人的 Twitter。查到时展示搜索和访问步骤、返回的账号/动态、链接及回复；空列表仍标为调用完成并保留空返回；HTTP 403、工具错误、审批中断等展示各自记录。界面不会从“未返回”推断“账号不存在”，也不从“已选技能”推断“已执行技能”。

## 分析与继续执行

- **新建分析并提问**：建立新的 RunDesk session 与 Codex thread，关联原任务、所选轮次、事件编号和创建时的最大事件游标。创建完成后将问题发送到新会话。创建或发送失败时保留问题，允许重试。
- **分析会话中的继续提问**：继续该分析会话。不会每问一句就新建会话，不会将解释性问题追加到原业务线程。
- **针对这一步追问**：把问题和事件引用填入分析输入框，用户点击发送后才创建分析会话。
- **打开已有分析会话**：原过程页列出当前轮次的已有分析；分析会话顶部可返回原任务过程。
- **继续原任务**：回到原任务对话；补充指令、停止、审批沿用原来的对话功能。

分析会话沿用原实例的模型、认证和工作区，来源类型为 human，并单独保存 traceOrigin；不会伪装成业务应用提交的新 taskId。分析请求使用只读文件沙箱，额外挂载会话级 `rundesk_trace` MCP。原实例的持久配置不被修改；这不是新的操作系统用户或完全隔离的配置环境，原实例的其他能力仍遵循其已有配置和权限。

## 给 Codex 的只读工具

| 工具 | 用途 |
| --- | --- |
| `trace_list_runs` | 分页列出来源会话快照内的轮次、问题摘要和状态 |
| `trace_find_steps` | 按轮次、类型、状态、关键词筛选步骤预览 |
| `trace_get_step` | 读取步骤预览、输入输出和原始事件编号 |
| `trace_read_event` | 按事件编号分段读取完整 JSON；可继续读取下一段 |
| `trace_statistics` | 分类计数、异常数量和已有完整边界的耗时统计 |

Codex 负责理解问题、选择工具并组织解释。工具只执行固定的参数化只读查询，不接收任意 SQL，也不执行日志中的命令。读取其他会话、读取快照之后的事件、写入数据库均不可通过这些工具完成。

分析范围为原会话截至创建时的记录，默认聚焦所选轮次；模型可以按用户问题比较该快照内的其他轮次。来源新增记录不会悄悄改变既有分析依据。需要最新记录时，从原过程页新建一次分析。

搜索匹配有界的事件预览；未匹配不能证明完整输出中不存在对应文本。完整内容通过事件分段读取。工具耗时使用后台接收时间，只有完整起止记录才计入；步骤耗时之和不等于总墙钟耗时。界面在原生时间存在时会使用原生时间，并注明依据，两种口径不可直接混同。

当前不接入 Text2SQL。以后需要跨任务统计时，可以在明确授权和只读视图上增加该通道；本版先保证单任务的定位、追问与证据可核对。

## 数据边界

原始记录来自 App Server 与 RunDesk 事件库，不推测隐藏推理、未记录的访问步骤或完整模型请求。已删除的原任务无法继续提供轨迹查询；关联信息会保留，但工具会明确报错。超过 100,000 条生命周期事件的来源快照会报出容量限制，不返回不完整统计冒充全量结果。

界面截图和 Twitter 查询演示使用虚构数据。原生 MCP 发现与调用以 Codex 0.159.2 验证，不等同于已验证真实模型的分析质量。
