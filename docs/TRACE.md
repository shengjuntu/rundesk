# 轨迹工作台 · v0.5.1

选择会话后，点击顶部「轨迹」。页面读取该会话已有事件，不需要重新执行任务；关闭页面或返回对话不会停止后台运行。

![轨迹工作台，使用模拟数据](screenshots/trace-workspace.png)

## 看一次运行

1. 顶部选择单次运行，或保留「全部运行」查看多个任务之间的间隔。概览给出观测跨度、已结束审批等待的合并时长、异常步骤数和原生线程累计 Token。
2. 全程总览中的选区表示当前时间范围。拖动选区平移，拖动两端缩放；也可在主轨道滚轮缩放、空白处拖动平移。点击「适应全程」恢复全貌。
3. 点击色块或下方步骤列表，详情显示输入、输出、状态、时间依据与源事件。选中线同步出现在总览和各轨道；未选中的文字保持清晰。
4. 时间很短或过于密集时，使用「按步骤」。此模式等距排列，宽度不再表示耗时。
5. 底部提供上一/下一步骤、上一/下一异常。左右方向键切换步骤，Shift+左右切换异常，+/- 缩放；输入框中这些快捷键不接管输入。

## 六类轨道

| 轨道 | 来源 |
| --- | --- |
| 输入与回复 | RunDesk 提交记录、原生 userMessage / agentMessage |
| 可见模型阶段 | 原生 reasoning item 的生命周期与公开内容；不代表完整模型 HTTP 请求 |
| 命令与 MCP | commandExecution、mcpToolCall、dynamicToolCall，以及文件、搜索和图像工具 item |
| 审批与确认 | approval/pending、approval/resolved、serverRequest/resolved、过期记录 |
| 上下文与注入 | 已记录的项目笔记、显式选中 Skills、原生 contextCompaction / thread/compacted |
| 状态与异常 | 原生错误、配置或运行告警，以及后台失败记录 |

「轨道」菜单可隐藏类别；文本搜索覆盖标题、已加载内容、工具类型和 item ID。「仅异常」保留失败、拒绝、中断、过期和告警。搜索针对有界预览；检索完整原始文本请使用原有调试台。

## 详情与原始记录

详情先展示可读文本，再提供折叠的结构化数据。预览单段文本最多 4 KiB，超长内容会标注截断；单条生命周期记录的文本预览预算为 16 KiB。

源事件按钮按稳定 ID 读取完整记录。页面最多显示该原始 JSON 的前 100,000 个字符，仍可下载完整单条事件。完整会话的 JSONL 导出继续保留逐字 delta。

「导出轨迹」下载当前运行和筛选后的语义索引（`rundesk-trace/1`），包括源事件 ID。它不是完整原生日志，不支持作为 Codex 线程导入。分享前检查命令、路径、内容和输出中的敏感信息。

## 时间与指标的含义

- item 同时提供 startedAtMs / completedAtMs 时使用原生时间，否则使用对应事件的后台接收时间；详情明确标出依据。
- 缺少开始或结束记录时用虚线展示已观测范围，并标记端点不完整，不补造最终耗时。后台中断后的未闭合步骤也如此。
- 活跃任务的右边界随后台观测时间更新，不表示工具已经结束。点击步骤、拖动或缩放会关闭实时跟随；重新点击「跟随实时」可恢复。
- 审批等待从应用记录 pending 到首个有效结束记录。多个结束通知不会重复累计；重叠等待使用区间并集。尚未结束的等待不进入顶部已闭合等待总计。
- 命令条显示整个 item 的墙钟区间，可能包含审批等待；不要直接当作纯 CPU 执行时间，也不要把各轨道耗时直接相加。
- 全部运行的「观测跨度」包含任务之间的空档。选择单次运行可检查该任务的跨度。
- Token 为选中范围最后报告的线程累计值，不是单次运行用量或当前上下文占用。没有数据时显示“未提供”。
- 显式选中 Skill 只证明提交；MCP 工具调用需有实际 item 事件。界面不推断完整隐藏推理、系统上下文或全部 Codex 原生记忆。

## 长轨迹与恢复

轨迹接口按固定快照分页读取生命周期记录，排除逐字 delta；每 1.8 秒读取新记录。步骤列表只挂载可见行。时间轴同一轨道最多显示三层重叠，超出的步骤有计数提示，可缩放或在列表中定位。

刷新后恢复本浏览器标签页中的运行、筛选、选中步骤和视窗。专注模式隐藏详情，手机详情使用抽屉；收起后可继续选其他步骤。版本验证覆盖 2,001 步列表，尚未验证百万级生命周期索引。

演示：以 `--demo` 启动，输入“轨迹 审批”，会生成命令失败、MCP 和压缩等模拟记录。图中的数据也是测试夹具，不是真实模型结果。

## v0.5.1：定位耗时与导航边界

步骤索引右上可选「发生顺序」或「耗时从长到短」。耗时排序只影响列表；轨道和总览仍按真实时间排列，按步骤模式仍按发生顺序排列。完整、无时间冲突的区间参与排序；瞬时事件、缺失端点和未结束的步骤排在后面，不用当前等待时长冒充最终耗时。

「定位最长步骤」在当前运行和筛选范围内选择最长完整区间，并联动时间轴与详情。命令的整个生命周期可能包含审批等待，不能将它当作纯计算耗时。

普通上一/下一跟随列表顺序；异常上一/下一始终按发生顺序导航。边界处禁用按钮，不循环跳回。排序会随页面刷新恢复。

中断或后续新运行开始后，旧的未闭合步骤冻结在其运行最后的已记录事件，保持“端点不完整”。静止轨迹无新事件时不重建列表，保留已展开的源事件和键盘焦点。
