# RunDesk 0.29.0 / Kun 0.7.0

本版补齐 Kun 独立诊断入口。用户在“调试检查”选择轮次、固定证据范围并发送问题后，新的 Kun 会话使用同一模型分析历史记录，来源运行保持独立。原先 Kun 来源创建分析会话后无法启动的问题已解决。

- 诊断仅有六种固定来源查询及一个建议生成工具；不继承文件工具、业务 MCP、Skills、项目笔记、业务提示词或任务断点默认值。
- 建议分为检查、补充指令、配置调整，引用校验来源和运行归属；Kun 会话显示“待审核建议”卡片，可回到同一固定范围的原始事件。没有自动应用或重跑。
- 追问使用相同来源，模型请求和用量属于诊断会话；新记录须重新建立诊断范围。诊断输入只允许文本。
- 原 Codex 分析会话复用严格 trace 工具参数和建议输出；公共 debug-mcp 仍提供 19 个查询工具。
- 导出来源快照前检查事件数和大小；运行中的来源保持暂停/原状态，诊断不变更其 revision、事件或预算。

这推进了 K2 的诊断会话与证据建议链路；诊断器选择、建议应用整合、真实服务验收、K3 分叉/组合和 K4 优化仍待完成。引用校验不等于模型结论已经验证。

协议由 v6 升级到 v7，Kun 由 0.6.0 升级到 0.7.0，需要同时更新两个二进制。旧引擎检查点不能跨版本续跑，历史快照仍可检查。源码无新增第三方运行时依赖、不含二进制；Go 1.25.12+ 执行 `make build`。

接入与完整边界见 [KUN-DIAGNOSIS.md](KUN-DIAGNOSIS.md)，本次验证见 [KUN-VALIDATION.md](KUN-VALIDATION.md)，阶段完成度见 [KUN-PROGRESS.md](KUN-PROGRESS.md)。
