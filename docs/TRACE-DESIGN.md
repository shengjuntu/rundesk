# 单一 Turn 时间轴 · 0.8.1

0.8.0 已取消旧版按时间比例排布的多轨道，但仍是“左侧选轮次、中间看过程”。用户需要先读懂整段会话，因此 0.8.1 改为一个从上到下的时间轴，每个节点代表一轮提问及其执行记录。

## 调研与取舍

调研日期：2026-10-03。以下是对公开官方说明的设计判断，不是对这些产品的可用性排名，也没有集成其服务或复用其代码。

| 参考 | 采用的思路 | 在 RunDesk 中的具体处理 |
| --- | --- | --- |
| [LangSmith Trajectories](https://www.langchain.com/blog/langsmith-trajectories-tracing) | 先按发生顺序读会话中的动作，再深入底层 trace | 所有 Turn 在同一纵轴上；先显示问题和结果摘录，展开后查看工具和原始事件 |
| [LangSmith 数据模型](https://docs.langchain.com/langsmith/observability-concepts) | 区分跨轮会话、单次执行和执行细节 | Turn 作为主节点，调用留在对应节点内部，步骤输入输出放在按需打开的详情中 |
| [Langfuse Sessions](https://langfuse.com/docs/observability/features/sessions) | 将多次 trace 串成完整交互，便于回顾 | 保留前后轮次概览，原地展开，不通过侧栏反复切换上下文 |

## 阅读层级

- 概览：一条轴、多个 Turn。问题、实际回复摘录、工具次数、耗时、空返回和需关注项。没有自动生成额外总结，也不把“调用结束”标成“目标已实现”。
- 展开一轮：同一节点内显示助手回复、上下文提交、执行步骤和工具返回链接。长文本展开，步骤分页，其他节点保持概览。
- 查看一步：输入、输出、错误与证据编号；运行信息和原始 JSON 默认折叠。手机用详情覆盖面板，桌面保留侧边详情。
- 发起分析：底部标明选中 Turn，新建关联的独立分析 session；通过五个只读工具查询快照。后续追问留在分析会话。

一次只展开一轮，降低长会话的页面负担。时间轴是事件顺序，不是等比例时标；不添加多个泳道、拖拽缩放或装饰性的连接分支。新事件不抢走历史选择；显式“最新一轮”用于跳转。

搜索覆盖加载的轮次与有界预览。空返回是单独标记，并计入“需关注”筛选；它不自动等同于错误或不存在。按原始状态展示运行结束和工具失败，允许“本轮结束、其中某一步失败”同时存在。

## 实现边界

Go 服务、事件库、原生 Codex thread、实例配置和只读 MCP 均沿用 0.8.0。前端只改投影与交互，无新增产品运行依赖。使用现有事件接收顺序组织 Turn；运行中补充指令留在原轮次。缺失边界的历史记录保留不完整标记。

时间轴复用节点，选中轮次的详细内容容器在节点间移动；只有一个步骤列表和一份分析输入框。步骤仍每页 60 项，事件全量查询与原始下载不因分页丢失。筛选、展开和选择保存在当前标签页，分析草稿独立于原任务对话草稿。

只读分析仍使用来源会话创建时的固定快照；本次不引入 Text2SQL。原生会话级 MCP 协议验证范围见 [0.8.0 验证记录](VALIDATION-0.8.0.md)，0.8.1 的界面验证另记。
