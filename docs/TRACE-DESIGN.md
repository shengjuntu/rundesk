# 过程界面设计 · 0.8.0

核心单位是一次用户提问及其运行记录。界面从“按时间长度排列事件”转为“理解一次尝试得到结果的过程”。原有事件库和运行内核继续复用。

- 左侧：问题轮次。保持问题、过程和回复的归属，避免将历史失败混入当前状态。
- 中间：实际步骤、助手回复和来源。阶段、结果和失败均由记录支持，不生成虚构计划或伪造成功结论。
- 右侧：选择步骤后的输入、返回、时间依据与原始事件。复杂数据按需展开。
- 底部：针对过程发起分析。创建关联的独立 session；原任务与分析各自维护历史。继续业务执行通过明确的“继续原任务”入口。

分析依赖只读轨迹 MCP。会话级配置由 RunDesk 注入 thread/start 或 thread/resume；不写 config.toml。MCP 子进程复用 RunDesk 二进制，以 SQLite mode=ro 与 query_only 打开事件库，并固定 session ID 和最大事件游标。Codex 根据问题调用有界的查询工具。

不直接开放 Text2SQL：当前问题集中在具体步骤、失败、来源和耗时，有类型的接口足以表达，且能统一分页、预览与时间边界。以后跨任务分析的范围、权限和视图另行设计。

原六类比例轨道、缩放和平移控件已由新过程页取代；原始事件、历史查询、实时更新、步骤定位与导出仍然保留。历史 0.5.x 的设计说明和测试截图可通过旧发布包查阅。

协议依据：[App Server](https://learn.chatgpt.com/docs/app-server)、[MCP 配置](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)，并以本机 Codex 0.159.2 生成的 schema 和实际 RPC 验证。未发送模型推理请求。
