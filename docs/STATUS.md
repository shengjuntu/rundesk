# 当前状态与后续工作

RunDesk 0.49.0 / Kun 0.16.0 / worker 协议 16。这里只记录当前能力和缺口；“已实现”与“真实部署已验收”分别判断。

| 范围 | 当前实现 | 主要缺口 |
| --- | --- | --- |
| 应用平台 | 应用级 Docker 准备与工具发现、v1 API、应用凭据、任务队列、会话、事件、审批、文件、幂等、定时任务 | 分布式调度与完整多租户隔离未实现 |
| 启动配置 | 后端选择、本机依赖检测、Kun 独立初始化、可选固定版本 Codex 安装、原子保存与 revision 守卫 | 检查不证明真实模型/认证可用；实际 npm 下载、原生 Windows 部署需验收 |
| 后端抽象 | 统一运行/停止入口、静态能力目录、未知后端明确拒绝 | 配置、审批、恢复、执行环境尚未全面抽象；无动态插件 SDK 或 UHP 兼容入口 |
| K1 核心执行 | 模型工具循环、七类编程工具、MCP、审批、预算、动作账本 | Kun 容器、交互 Shell、Bash 流式输出、长文件分页、完整 PiG 生态未实现 |
| K2 轨迹调试 | 共同工作台、固定历史范围、结构化摘要与问答、Codex 直通模型观测；Kun 单步、断点、快照、检查点与独立诊断 | Codex 内部单步不可用；HTTP 采集仅覆盖实际配置并经过代理的请求，受正文/队列上限约束 |
| K3 实验与分叉 | 固定基线、Hybrid/Live、两套循环策略、安全切换、结果假设、同基线对照和规则评分 | 任意模块插件、完整依赖图、嵌套分叉和统计推断未实现 |
| K4 验证与复用 | 成功轨迹候选、独立验证、应用启停、守卫回退、重复配对对照、产物规则和固定文件目录 | 业务收益与生产负载需实际任务验证；领域裁判、外部状态隔离和可选 JEV 未实现 |

## 典型配置目录

本版采集、默认开关、Docker 网络要求与认证覆盖范围见 [统一调试与采集](UNIFIED_DEBUGGING.md)。当前实现保留实际请求/响应字节与原生工具事件，但不宣称所有 Codex 认证路径、任意长度请求或持久连接中每个轮次都已经完整采集。完整性由每条记录的标记与部署验证共同判断。

`examples` 已提供 news2douyin、people-search、video-build 三套 manifest、独立入口和统一 CLI；默认 Exa + 完整 Agent-Reach 基础工具链。初始化向导可在应用注册前选择配置，后台构建/拉取/检查已有镜像，复用缓存、展示日志、取消与重试，并完成离线工具检查。当前环境未实际构建容器，详见 [配置目录](../examples/README.md) 与 [验证](VALIDATION.md)。

## 下一步

1. 完成本版在用户部署环境的首次启动、Codex 安装/认证、Kun 真实模型和 Windows 验收。
2. 在现有生命周期入口上继续收敛后端配置、审批、恢复与执行环境接口，以契约测试保持原行为。
3. 接入 Kun 托管容器，明确身份、挂载、网络、资源和取消语义，再扩展 Bash 流式输出与文件读取。
4. 使用有代表性、允许重复执行的任务集验证 K4 的质量与效率收益，再决定新增裁判与统计能力。

核心 K1/K4 链路已可测试；不能将它们表述为完整 PiG 覆盖、OS 隔离或业务质量保证。验证依据见 [VALIDATION](VALIDATION.md)。
