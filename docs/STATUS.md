# 当前能力与后续工作

**RunDesk 0.75.0 / 独立 Kun 0.17.0 / worker 协议 16**。RunDesk 通过轻量 SDK 连接独立 Kun，不包含其执行内核；本版不改变 Kun、SDK 或 worker 协议版本。三个使命的产品定位见[中文 README](../README.zh-CN.md)。

0.75.0 增加本地完整目录获取、已安装 Skill 独立快照和显式环境诊断。获取只保存固定内容与内置检查；安装和效果执行仍需单独操作。诊断区分命令缺失、版本不兼容、受控自检失败与尚未验证的模型／认证状态。

0.74.0 在技能详情增加 Skill-Up 效果测试：容器内用例校验与执行、持久任务、外部报告导入、逐用例结果和跨版本比较。实际运行仅支持 Linux 本机 Docker，并需准备含 Skill-Up 的镜像；不可用保持失败，不使用宿主回退。导入报告与安全扫描分别展示，身份和用例证据不足不能形成通过的回归门禁。详见[效果测试](SKILL-CHECKS.md)。

0.73.1 用真实 SkillSpector CLI 验证安全检查接入，补上零文件／矛盾覆盖统计、遗漏文件与扫描期间内容变化的核对，保留文件级未覆盖原因。详情中 Go 与 NVIDIA 报告可分别查看，刷新后可恢复在途扫描。

0.73.0 增加管理员[技能中心](SKILL-CENTER.md)：四来源搜索、获取完整固定目录、源码预览、内置 Go 静态检查、可选外部 SkillSpector 后台扫描与安装回执。安装沿用工作区／环境及完整备份；风险或未覆盖项需显式确认和理由。该阶段没有实现运行时防护与历史会话技能内容冻结；Skill-Up 已在 0.74.0 独立接入。

本版为六套内置配方增加自动准备与复用的系统、媒体和浏览器公共层，沿用现有构建入口和日志。源参数、阶段输入、平台及实际镜像身份决定复用；Codex 与业务依赖继续在配方中安装。旧冻结上下文不改写，历史重建不使用后来移动的同名镜像。0.67.1 的 video-build 临时空间修复继续保留，构建成功与 offline/smoke 通过仍分别记录。用户提供的同镜像 17/17 检查结果与本版回归范围分别归档在[验证说明](VALIDATION.md#video-build-tmpfs-investigation-2026-11-08)。

## 围绕三个使命的能力

| 使命 | 当前实现 | 主要边界 |
| --- | --- | --- |
| 企业 Agent 落地调试 | Codex/Kun 共同轨迹工作台、对话式阅读、统一 observation/activity、固定历史范围、只读 HTTP/MCP 查询与独立诊断；Kun 提供单步、断点、快照、检查点 | Codex 不暴露 Kun 内部控制；HTTP 观测默认关闭，只覆盖经过代理且实际保留的证据；无法补回未采集内容 |
| 应用与 Harness 连接 | RDCA、UHP 服务入口、应用凭据、持久任务队列、会话、事件、审批、文件、幂等、定时任务、命名运行预设、构建中心；UHP 严格能力准入、含排队的持久时限、进度查询及审批工作台入口 | UHP 不执行硬工具轮次/输出 token 预算，指令以文本保留在会话历史；命名预设目前绑定 Codex Docker；原生插件安装/卸载、分布式调度与完整多租户隔离未实现 |
| Harness 开发与研究 | Kun 模块检查、两套循环策略、安全切换；研究 API 保留离线实验、Hybrid/Live 分叉、任务集、规则评分、重复采样及参数化工具流程验证 | 四项研究工具已撤下日常启动入口；主要为 Kun 能力，无任意模块动态加载 SDK、完整依赖图或嵌套分叉；业务收益须由实际任务评测确认 |

## 运行、资源与扩展

- **实例与配置**：WebUI 以实例为配置入口；Docker 后端仍按“实例 × 工作区”保存独立配置与运行状态。脱敏配置快照用于加快显示，后台同步只更新该副本；跨工作区配置版本应用、自动收集统一能力库、跨 Agent 格式适配尚未实现，不能将页面集中理解为配置已全局同步。
- **后端**：Codex 与 Kun 由独立运行模块及显式宿主服务接入，共享任务准入、取消和资源契约。新增后端仍需代码适配与契约测试，不是登记一个名称即可使用。见[后端能力](BACKENDS.md)与[资源契约](RESOURCE-CONTRACTS.md)。
- **API**：RDCA v1 使用 `/api/v1`；UHP `/v1` 的协议仍为 `2026-10-19`。UHP 通过 `metadata.rundesk_require` 在任务和附件物化前拒绝所需但不支持的能力；默认任务时限 3600 秒，包含排队时间；APP 可轮询进度并将待审批用户引向工作台。标准 SSE 不新增私有进度事件。两入口共用任务核心，不依赖 HarnessRouter 服务，不声明完整 UHP conformant。见 [UHP 范围](UHP.md)。
- **预设与构建**：一个应用可登记多个管理员批准的命名预设，分别固定 Codex Docker 实例与工作区，凭据精确授权。构建配方、镜像、运行预设、Skills、MCP 和插件是可组合资源；登记预设不代表资源已安装或账号已认证。构建目录和源列表可独立修改，镜像可显式拉取、复用或构建后选择；公开分发条目与来源镜像分别校验。见[运行预设](APPLICATION-RUNTIME-PRESETS.md)、[构建中心](BUILD-CENTER.md#build-workbench)与[下载源](BUILD-SOURCES.md)。
- **插件**：提供 Codex build-tools 插件包、Codex/Kun 构建 Skill 与限于任务的 MCP；支持原生包只读检查和已观察到的组件来源。稳定原生安装/卸载接口未接入，Kun 不加载 Codex 插件。见[插件能力](NATIVE-PLUGINS.md)。
- **启动与执行环境**：首次页面支持本机发现、Kun worker/模型验证、可选固定版本 Codex 原生受管安装和预构建镜像下载、本机构建或本地镜像检查；失败可交给受限 Kun 修复并记录经验。Kun 容器托管仍待实现，Bash 为显式授权的宿主执行。见[部署](SETUP.md)。
- **文件与任务资源**：新产物默认保留原件引用，需要冻结时显式保存快照；旧托管副本仍可读取。任务资源目录是可重建视图，不是另一份任务状态源。见[个人文件](PERSONAL-FILES.md)与[任务资源](TASK-RESOURCES.md)。

## 示例应用

[配方目录](../recipes/README.md)包含 news2douyin、people-search、video-build、HyperFrames、video-use 和 OpenMontage 六套运行配置。它们演示不同领域如何使用 RunDesk，具体依赖、应用配套版本和操作流程在各自文档维护。工具环境与业务应用分别部署；工具检查通过不等于真实模型任务或业务制品已经验收。

[UHP Python 客户端](../clients/python/uhp_client.py)提供上传、幂等提交、轮询、续接、取消和产物下载的最小接入流程。示例区分客户端观察超时与服务端任务时限，遇到待审批时返回控制权，便于 APP 接入自己的用户流程。

## 后续工作

公开分发上线还需维护者提供实际仓库账号/目标地址，上传验证过的镜像、设置公开可见性，并在国内和国外目标网络验收匿名下载；本版不预填虚构的官方镜像。

1. 完善实例配置的版本与作用范围，在保留工作区运行状态的基础上实现跨工作区应用；另行实现能力定义收集、复用及 Agent 格式适配。
2. 在目标部署环境验收 Codex/Kun 真实模型、Docker 回调、模型认证、Windows 运行，以及代表性应用任务。
3. 持续完善后端配置、审批、恢复和执行环境契约；补齐 Kun 托管容器及交互 Shell、Bash 流式输出等能力。
4. 在稳定后端接口具备条件时完善插件生命周期，减少应用预设准备中的手工配置。
5. 用可重复执行的任务集验证 Harness 策略和 Skill 复用的质量、成本与适用范围，再扩展裁判和统计能力。
6. 完成 UHP 真实 APP–Codex/Kun 闭环验收；仅在后端提供可靠契约后实现硬工具轮次、输出 token 预算和原生指令语义。harness 写入等 Full 管理能力按应用需求扩展，不把平台配置与调试职责全部搬入 UHP。

本版检查及未覆盖范围见[验证说明](VALIDATION.md)。用户提供的六套配方实机构建经验独立保留在[运行时说明](BUILD-RUNTIME.md#这次实机修复的来源)，不计作本版回归结果。
