# 个人文件库（0.13.0）

## 已确认的产品约定

本版按用户确认的简化方案实现：文件库是个人的；上传和会话生成的文件默认入库；输入框「＋」可以选择上传或从库中加入；提供删除功能。不加入知识库、项目库、共享库、文件发布审批或版本配置界面。

## 使用

- 点击「我的文件」查看个人文件，按文件名搜索、预览、下载或删除。
- 在任意会话点击「＋ → 上传文件」，附件上传完成即自动保存到个人库。
- 点击「＋ → 从文件库加入」，选中已有文件作为当前会话的附件。再次引用不新增库条目。
- 会话结束时，自动保存本轮新增或修改的正式产物。模型收到的提示要求将产物写入 `outputs/<sessionId>`；工具缓存、源码依赖和工作区其他文件不当作会话产物。
- 删除会话不会删除个人库文件。删除库中文件后，不再出现在列表，不能重新加入；历史附件引用显示已删除，下载返回 410。

生成的每份产物作为当时内容的独立文件保存；以后同名产物被修改，不会改写已经保存的文件。不向用户暴露版本管理概念。

## 个人归属

管理员登录对应管理员自己的库，普通用户各有自己的库。所有权由服务端从认证身份取得，不能由请求参数指定。即使两个成员属于同一应用项目，也不能查看对方的个人库。

将个人文件加入会话，会把内容提供给该会话及其执行环境。已有应用项目仍采用原来的共享任务权限；这次没有改变会话的可见范围。文件库本身不提供共享入口。

生成文件归本轮任务的发起人。共享会话中后续用户仅收录自己轮次新增或修改的产物，不自动收录此前其他人的文件。通过个人身份提交的队列任务和恢复轮次也保留归属。纯应用 API 凭据没有个人身份，不能访问个人库，也不会把后台任务文件放入某人的库。

## 保存和删除

文件与目录在宿主机 `<data>/personal-files/<owner>/<fileId>`，不随容器销毁。跨会话加入时从个人库创建工作区附件副本，既有 Docker 挂载和原生 Codex 输入机制继续使用；库中不生成重复条目。

删除会移除个人库的文件内容并保留引用墓碑。RunDesk 会阻止该文件历史引用的下载和再次提交。但它不是对已执行任务的撤销：此前交给模型、已进入工作区的副本、模型自行复制的文件和既有备份不会被追溯擦除。

上传保持原有单文件 32 MiB 限制；生成文件自动保存上限 512 MiB；个人库最多 10000 个有效文件、10 GiB。容量或磁盘错误会返回结构化错误，自动收录失败记录为 `library/error` 执行事件，不假装保存成功。支持文本、常用图片、音频和视频预览，其他格式下载查看。

升级前文件没有可靠的个人所有权记录，因此不自动猜测归属和批量导入。旧文件仍可从原会话获取，需要时重新上传到个人库。

## API

使用个人 Cookie、个人访问码或管理员认证；应用凭据无权调用。

- `GET /api/v1/library?q=文件名`：当前人的文件列表。
- `POST /api/v1/library`：multipart 字段 `file`，直接上传到个人库。
- `GET /api/v1/library/{fid}/content`：下载，`preview=1` 请求支持格式的安全预览。
- `DELETE /api/v1/library/{fid}`：删除本人的文件。
- `GET /api/v1/library/deleted-references`：本人的历史引用墓碑，用于展示已删除状态。
- 原有 `POST /workspaces/{wid}/uploads` 除 `file` 外，可用 multipart 字段 `libraryFileId` 引用自己的库文件。成员仍通过 `/member/{grantId}/workspaces/{wid}/uploads`，项目写入权限照常检查。

OpenAPI 版本 1.12.0。不添加搜索引擎、向量数据库或新的运行依赖。
