# 升级到 RunDesk 0.8.3

停止旧服务，替换程序，沿用原用户、数据目录、CODEX_HOME 与启动参数，刷新浏览器。无需数据库迁移。包内有 Linux amd64 和 Windows amd64 二进制；Windows 仅交叉编译。

本版修复连接阻塞、失败清理和任务确认问题，保留 0.8.2 的错误记录界面。v1 的已识别上游错误改为 502/503/504，原始原因、requestId 和幂等语义保留。旧 `/api` 业务错误状态保持兼容（请求记录读取故障统一为 503），新增错误代码可用于诊断。已有接收回执按原状态回放，不改写；回执字段损坏时拒绝回放，不重新执行。

API 描述升级到 1.3.2，ErrorDetails 增加 codex_transport 来源与可选 transportOperation。见 [发布说明](RELEASE-0.8.3.md)、[500 与运行错误排查](HTTP-FAILURE-AUDIT-0.8.3.md)。

# 升级到 RunDesk 0.8.2

本版增加页面请求与运行错误的详细诊断。停止服务，替换程序后沿用原用户、数据目录、CODEX_HOME 和启动参数，刷新浏览器。无需迁移数据库，也不会因升级重新执行任务。

主页面和轨迹页新增「错误记录」；登录页也可查看连接失败信息。错误提示中的「查看详情」以及运行错误卡片中的「查看错误详情」可直接打开对应记录。本版保留单轴 Turn 时间轴及独立分析会话。

OpenAPI 更新到 1.3.1，错误响应新增可选 details；原有 error/code/requestId/retryable 保留。已有幂等回执不改写，回放时可能没有 details。详见 [0.8.2 发布说明](RELEASE-0.8.2.md) 与 [诊断说明](DIAGNOSTICS.md)。

# 升级到 RunDesk 0.8.0

停止旧服务并备份数据目录与 CODEX_HOME，替换程序后沿用原启动参数。0.7.0 数据无需搬迁；已有事件由新过程页直接读取。刷新浏览器加载新的内嵌界面。

本版增加 session 的可选 traceOrigin 元数据，没有删除或重新执行旧任务。「新建分析并提问」才会创建新的分析会话。分析会话的工具仅读取原会话截至创建时的事件；需要查看后续新增事件时，可从更新后的原任务过程新建分析。

内置轨迹 MCP 通过 RunDesk 程序本身启动，不需安装 Node、Python、数据库服务或额外搜索 API Key。模型仍使用已有 Codex 登录/Provider 配置；真实模型问答会按该配置运行。本轮原生工具验证版本为 Codex 0.159.2。

新轨迹页取代原六类时间比例轨道、缩放和平移布局；事件和原始记录继续保留。完整说明见 [TRACE.md](TRACE.md) 与 [0.8.0 发布说明](RELEASE-0.8.0.md)。

# 升级到 RunDesk 0.7.0

停止原服务并备份数据目录、项目和各 CODEX_HOME。将新包解压到独立程序目录，替换服务使用的二进制；保留原系统用户、`--data`、`--codex`、CODEX_HOME 和服务参数。不要同时运行两份后台。`bin/rundesk --version` 应显示 0.7.0，重启后刷新浏览器。

本版沿用数据库与执行内核，只增加应用登记元数据。原 default 配置用于通用助手；一对一的历史应用来源自动登记。无法判断归属的旧配置在「应用 → 接入说明与历史配置」查看或手动登记。原会话、线程、事件、笔记、技能目录和 MCP 配置保留；未完成的运行仍按原规则中断，不自动重跑。

news2douyin 0.11.1、video-app 0.5.1 可继续使用。已经有任务的应用升级时归类；只完成配置但尚未发起任务的应用，可手动登记或等待它提交首条带来源的任务。新客户端也可在第一次任务前调用 `PUT /api/v1/applications/{appId}` 登记。应用在其他配置上重复登记/发起新会话将返回绑定冲突，不会自动改写归属。

Skills 与 MCP 的设置按钮现在进入独立页面。现有技能文件夹无需转换。导入 ZIP 支持根部 SKILL.md，或一层技能文件夹；脚本、参考资料和资源作为普通文件保留，空目录不单独归档。同名替换与完整移除会备份整个目录；旧版只写入 SKILL.md 的 API 保持原有语义。

本包包含 Linux amd64 和 Windows amd64 二进制。Windows 版本为交叉编译，未做 Windows 实机验证。真实模型认证及外部 MCP 仍在你的部署环境验收。

# 升级到 RunDesk v0.5.0

适用于 v0.2、v0.3 或 v0.4。停止后台并备份原数据目录、工作区和各 CODEX_HOME；将新包解压到独立程序目录，替换原服务使用的二进制，保持原用户、--data、--codex、CODEX_HOME 与服务参数。运行 `bin/rundesk --version` 应显示 0.5.0。

在轨迹页选择单次运行，检查命令、审批等待和详情；原始增量保留在事件日志里。返回对话后继续使用原有审批和配置界面。重启使未完成任务中断、旧审批失效，只有再次发送消息才会继续任务。

# 升级到 RunDesk v0.4.0

适用于当前 v0.2.0 或 v0.3.0。先停止 RunDesk，备份原数据目录、外部工作区和各 CODEX_HOME，再替换程序。保持原系统用户、--data、--codex、CODEX_HOME 与服务启动参数。

1. 将本包解压到单独目录，不要覆盖数据目录。执行 `chmod +x bin/rundesk`、`bin/rundesk --version`，确认 0.4.0。
2. 将新二进制安装到原服务 ExecStart 指向的位置；保留旧二进制与备份用于回退。仅替换二进制且服务参数未变时不需要 daemon-reload。
3. 启动原服务，刷新浏览器。旧会话、实例、事件、项目笔记和 thread ID 保留；v0.2 会话自动绑定默认实例。
4. 旧实例补充权限缺省值：workspace-write / on-request / user；网络沿用 Codex 配置。没有自动扩大权限。
5. 打开「配置 → 运行配置 → 运行连接诊断」，查看沙箱实际执行、原始错误及启动告警。
6. 新建会话测试普通文件读取。旧对话可能保留“沙箱失败，应提权”的历史判断，不能用它代替新环境验收。

后台重启后旧运行标为中断、旧审批失效，不自动重跑。下一条消息继续原 thread。修改实例权限只在下一轮生效；进行中的任务和待审批请求保持原策略。确认实际值请打开对话顶部「查看运行配置」。

回退时停止新版本并恢复升级前数据备份。旧版本不理解 v0.4 权限元数据，不应让它重新保存实例配置，也不要用 v0.2 打开包含新实例会话的数据。

# v0.3 历史升级说明

## 从 v0.2 升级

1. 停止旧服务，等待进程退出。备份原 `--data` 目录、外部工作区及原 CODEX_HOME；保留数据库可能存在的 WAL/SHM 文件。
2. 解压新包到单独的程序目录。继续用**原系统用户、原启动参数、原数据绝对路径、原 CODEX_HOME**启动新二进制；无需移动项目。
3. 打开页面确认版本为 0.3。旧会话将自动绑定 `default` 实例，thread ID、事件、笔记、置顶和归档保留。
4. 通过「配置 → 实例」新建助手，再配置实例 Skills 和 MCP。新实例没有复制旧配置，也没有自动登录。

```bash
# 替换成旧服务实际使用的数据绝对路径
./bin/rundesk --version
./bin/rundesk --data /原来的/rundesk-data
```

若此前用默认数据路径，可保持不传 `--data`。如果使用 systemd，按 [Ubuntu 指南](UBUNTU.md) 更新二进制并重启；不要同时启动第二份服务。

升级会新增 instance 对象并给旧 session 补充 instanceId。默认实例在每次服务启动时跟随服务的 CODEX_HOME，因此更换这个环境变量会让旧 thread 找不到；它不是用来切换助手的入口。用 WebUI 创建新实例即可。

旧 API 未传 instanceId 时仍选择 default，Skill 文件 CRUD 未传 scope 时仍操作 project；WebUI 新建 Skill 默认选择 instance。会话无法 PATCH 到其他实例或工作区。回退须停止服务并恢复升级前备份，旧版本无法正确路由新实例的会话。

新实例的 Codex 数据位于 `--data/instances/<id>/codex/`；默认实例的原生状态仍在原 CODEX_HOME。实例 Skill 移除备份相对于各自的 CODEX_HOME，项目 Skill 备份相对于工作区。两种范围均保留附属文件。

## v0.1 → v0.2 的兼容说明（仍适用）

## 数据与启动

1. 停止旧版后台。正在运行的任务不会自动迁移为继续运行的任务。
2. 在旧服务已停止时备份旧数据目录（包括 state.db 以及可能存在的 WAL/SHM 文件）、工作区与 CODEX_HOME。工作区可能位于数据目录以外。
3. 解压 RunDesk，新版本程序使用旧数据目录启动：

```bash
./bin/rundesk --data /原来的/codex-base-数据目录
```

若旧版使用默认目录，RunDesk 在没有自身数据库时会自动检测用户配置目录下的 `codex-base/` 并原地使用。检测包括真实模式和 demo 子目录。若新旧两个目录都已有数据库，默认使用 `rundesk/`；可用 `--data` 明确选择。

**不要为了更名直接移动工作区。** 数据库和 Codex 原生线程中包含工作区绝对路径。这个版本通过原地复用旧目录保持路径与 thread ID。`--data` 指定的是旧数据目录的根；使用 `--demo` 时程序自动附加 `demo/`，不要重复附加。

v0.1 数据可直接读取：置顶/归档字段缺省为 false，原会话标题、原生 thread ID、笔记与事件保留。后台重新启动后，未完成任务标记为中断，旧审批失效。再次提交才会继续原生线程，不会自动重跑旧输入。

## 会话与配置行为

- 归档保留上下文、事件与文件；恢复后可继续原生线程。
- 删除仅清理 RunDesk 的会话、审批和事件。原生 Codex 历史、上传文件和 outputs 产物保留，便于单独管理。
- Skill 移除会备份入口文件至 `.rundesk/skill-backups/<名称>-<标识>/SKILL.md`，附属文件保留在原目录。需要恢复时，将该内容重新导入同名项目 Skill，并确认启用开关。
- MCP 导入不会删除未出现的服务。同名服务默认拒绝覆盖。导出会隐藏 env/http_headers 等结构化密钥，但 args、URL 或文本里可能仍有敏感内容；共享前检查。

如需回退，请停止 RunDesk 并恢复升级前备份，再启动旧程序；不要让两个版本同时访问同一数据库。源码仓库的 module 路径仍为 `github.com/shengjuntu/rundesk` 占位符，发布到自己的仓库时统一替换即可。
