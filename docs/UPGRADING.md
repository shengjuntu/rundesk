# 升级到当前版本

当前版本 RunDesk 0.49.0，配套 Kun 0.16.0、worker 协议 16、fork schema 3。

1. 停止原服务，备份数据目录、工作区、Codex 配置及服务环境设置。
2. 从新源码构建两个程序，放在同一可执行目录；保留原系统用户、`--data`、`--codex`、`--kun`、CODEX_HOME 与服务参数。
3. 启动后用 `rundesk --version` 和 `kun --version` 核对，刷新浏览器。已有配置与历史任务继续读取；重新检查本机依赖。
4. 本版不会自动安装 Codex、切换后端或启用 Bash。向导中明确安装并保存才生效；更换后端后新建会话，历史会话保持原归属。

从 0.44.0 / 0.45.0 / 0.46.0 升级，Kun 内核和协议未变；未修改历史实验、检查点或 Skill 的执行语义。更早 Kun 版本的预览/检查点若被版本守卫拒绝，应按当前内核重新运行来源、创建预览及独立验证，不绕过守卫。历史只读报告仍可查阅。

重启不会重放已开始或结果未确认的任务；排队任务保留。检查原回执、任务状态与副作用证据后再决定后续操作。自动重试与重新提交不是一回事。

使用可靠的本地文件系统；一个数据目录只运行一个 RunDesk。`server.lock` 为内核锁载体，长期保留正常，运行时不能删除。非常早期版本的旧格式锁应先确认旧服务已停止再处理；不要通过删除锁并行启动服务。

本轮新增应用运行环境接口；配套新闻应用需升级到 0.13.1。旧新闻配置保持本机模式，选择 Docker 后按其部署文档完成镜像与模型认证，业务工具安装到容器环境。运行准备不会替换管理员选择的镜像或恢复被删除的能力。不删除运行数据、用户文件、会话或实验记录。详细历史在此前交付版本包中保留。当前能力与限制以 [STATUS](STATUS.md) 和 [VALIDATION](VALIDATION.md) 为准。

## 0.47.0 升级到 0.47.1

先停止研究并保留原数据目录，替换 RunDesk/Kun 程序；Kun 内核版本不变。升级 news2douyin 到 0.13.1，在研究设置选择 Docker 完整访问并“连接并配置环境”，为既有环境补齐运行权限及持久 MCP 审批。仅更新程序不会自动放宽旧实例权限，也不会自动接受已弹出的审批。现有镜像中的 Codex 若支持服务级审批配置，无需仅为此次设置修改重建镜像；不支持时构建明确版本后显式更新环境。

## 0.48.0：Exa 与初始化镜像准备

替换 RunDesk 二进制；Kun 0.16.0 不变。停止旧服务并使用相同数据目录启动，打开初始化向导准备 `news2douyin` 镜像。镜像工具层已改变，旧镜像不会被原地补齐；首次请构建或拉取新配方 1.1.0 的镜像。

配套 news2douyin 升级到 0.13.2。新研究设置从 Wigolo 迁移为 Exa；“连接并配置环境”会启用 Exa 并停用旧 Wigolo，同时保留其他 MCP、自定义 Exa 地址和凭据。正在执行的旧任务仍保留历史后端快照，应先结束后再切换环境。若已有环境绑定另一镜像，需在 RunDesk 显式更新，不会通过重连悄悄替换。

首次无需公共仓库账户即可本机构建；公开镜像仍需由发布者实际构建、验收并推送，本源码包未发布公共镜像。

## 0.49.0：统一调试与直通观测

替换 RunDesk 程序并刷新浏览器，原来独立的轨迹、只读检查和 Kun DevTools 入口统一为“调试工作台”。历史数据继续读取，Kun 版本和协议不变；旧版本未保存的模型 HTTP 正文不会补回。新观测以附加事件写入现有数据库，并增加事件索引。

代理默认启用并监听随机回环端口；支持的 Codex provider 使用线程级地址覆盖，不永久修改其模型配置。内置 provider 使用原生 `openai_base_url`，明确认证路由后才推导默认上游；无法确认时保留原连接并标记缺口。要关闭新增正文采集，启动时传 `--observe-http=false`。正文副本可能包含提示词、业务资料和工具参数，应纳入原数据目录的访问与保留策略。

Docker 场景显式配置 `--observe-listen` 与 `--observe-advertise`，确认容器到宿主的私有网络可达；没有配置时保留原模型连接并标明采集缺口。不要把“configured”当作真实模型链路已验证。完成一轮后检查请求、响应、采集标记，再判断该认证/网络路径是否满足调试要求。详细操作见 [统一调试与采集](UNIFIED_DEBUGGING.md)。
