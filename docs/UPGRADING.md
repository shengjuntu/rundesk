# 升级到当前版本

当前版本 RunDesk 0.46.0，配套 Kun 0.16.0、worker 协议 16、fork schema 3。

1. 停止原服务，备份数据目录、工作区、Codex 配置及服务环境设置。
2. 从新源码构建两个程序，放在同一可执行目录；保留原系统用户、`--data`、`--codex`、`--kun`、CODEX_HOME 与服务参数。
3. 启动后用 `rundesk --version` 和 `kun --version` 核对，刷新浏览器。已有配置与历史任务继续读取；重新检查本机依赖。
4. 本版不会自动安装 Codex、切换后端或启用 Bash。向导中明确安装并保存才生效；更换后端后新建会话，历史会话保持原归属。

从 0.44.0 / 0.45.0 升级，Kun 内核和协议未变；未修改历史实验、检查点或 Skill 的执行语义。更早 Kun 版本的预览/检查点若被版本守卫拒绝，应按当前内核重新运行来源、创建预览及独立验证，不绕过守卫。历史只读报告仍可查阅。

重启不会重放已开始或结果未确认的任务；排队任务保留。检查原回执、任务状态与副作用证据后再决定后续操作。自动重试与重新提交不是一回事。

使用可靠的本地文件系统；一个数据目录只运行一个 RunDesk。`server.lock` 为内核锁载体，长期保留正常，运行时不能删除。非常早期版本的旧格式锁应先确认旧服务已停止再处理；不要通过删除锁并行启动服务。

本轮清理的是源码包内重复历史文档和验收副本，不删除运行数据、用户文件、会话或实验记录。详细历史在此前交付版本包中保留。当前能力与限制以 [STATUS](STATUS.md) 和 [VALIDATION](VALIDATION.md) 为准。
