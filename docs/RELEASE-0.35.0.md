# RunDesk 0.35.0 / Kun 0.11.0

本版完成 K3-C 的普通运行安全点组合切换首批。管理员可在模型请求前已暂停、没有待处理工具/审批/控制或未知结果动作时，切换 Tool Loop 与 Plan-Act。

- Layers 提供原因、固定状态版本的预览与明确应用；历史快照只读，状态/输入变化使提案失效，重复点击和同请求重试受保护。切换后仍暂停，不自动调用模型或工具。
- 重置 memory/planning 状态，保留历史、权限、工具目录和累计预算，记录新的 Harness revision。切入 Plan-Act 后，继续时新增规划调用；切出后不再注入旧计划。
- 原始启动配置和 runtimeHarness 覆盖分开保存。检查点恢复和 Hybrid/Live 分叉保留有效组合与已完成计划；普通新轮次回到配置默认值。来源/历史快照保持不可变。
- 状态、迁移说明、回执与检查点在同一事务提交，失败时撤回内存迁移并停止。仅管理员可调用 set_harness；应用和成员权限不扩展。
- 不新增 API 路径或运行时依赖，仍为 150 路径 / 180 操作。worker hello 新增 runtimeHarness=true。

需同时更新 RunDesk 和 Kun：Kun 0.11.0 / worker v11；旧执行记录仍可查看，旧检查点和分叉预览不可跨版本执行。Codex 内部调试能力未新增。

K3 仍缺更多模块实现/迁移、跨会话基准及真实环境验收，K4 尚未实现。真实浏览器、远程模型/MCP、Windows 实机和生产环境未验收。完整证据见 [验证记录](KUN-VALIDATION.md)，操作与边界见 [KUN-HARNESS.md](KUN-HARNESS.md)。
