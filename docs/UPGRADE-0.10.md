# 升级到 0.10.1

1. 停止旧版 RunDesk，完整备份原 `--data` 目录和外部 workspace.path 项目目录。保留原绝对路径，勿直接移动 CODEX_HOME。
2. 替换二进制，以相同 `--data` 路径启动。已有实例、会话、任务队列、Cron、应用凭据和技能目录原位读取，已有应用保持本机模式。
3. 通用助手不需要 Docker。需要容器化的应用先准备 Linux 本机镜像，再进入「应用 → 运行环境」保存配置，创建独立项目并启动。
4. 点击每个环境的「配置此项目的能力」重新配置认证。不会自动复制通用助手或旧本机应用的账户、MCP 凭据和历史。
5. 新建会话/业务任务使用新环境。原会话绑定原执行方式；先前排队的任务也保持原绑定。切换前请先处理已有队列，必要时在核对副作用后重新提交。
6. 原生模型权限仍参与容器运行；目标主机的 Codex 沙箱、网络、认证、MCP 和实际工具执行需单独验收。

停止、移除、重建容器均保留宿主机数据。「重建」使用当前应用固定版本（未登记时解析镜像标签）和当前资源配置；「移除后启动」仍使用此前固定的镜像 ID。

回滚请停止 0.10，并恢复升级前的完整备份；旧版本不理解 Docker 会话绑定，不要让旧二进制直接运行包含 Docker 会话的新数据。回滚前需在 0.10 环境页面停止相关容器。不要删除宿主机目录或执行全局 docker prune 作为升级步骤。

详细主机要求、镜像模板和验收命令见 [DOCKER-ENVIRONMENTS.md](DOCKER-ENVIRONMENTS.md)。

0.10.1 新增镜像目录，无需搬迁数据；旧环境继续沿用原快照，应用目标变更不会阻止它继续工作。详见 [镜像管理](IMAGES.md)。
