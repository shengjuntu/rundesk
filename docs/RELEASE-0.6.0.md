# RunDesk 0.6.0：应用 API 与实例配置

本版实现之前约定的第一步升级：RunDesk 同时服务直接使用 WebUI 的人和调用 API 的应用。保留 Go + 内嵌 HTML/JavaScript，不增加 Node 运行依赖。

## 使用变化

- “配置”首先进入实例总览，集中进入模型与认证、Skills、MCP、运行诊断。页头始终显示当前实例和工作区。
- 会话标题下方显示绑定实例、模型、来源应用，点击“查看能力”可读取 Skills/MCP，以及上次任务实际运行记录。
- 默认模型可从可用模型清单选择，保存后用于新会话。已有会话的模型保持原值。
- Skills 标明实例、项目或其他来源。MCP 编辑明确提示影响范围；会话面板不复制配置、不伪装成会话隔离。
- 登录仍由 Codex 自己管理，实例页保留对应 CODEX_HOME 的登录命令与状态检查；没有复制用户认证或直接编辑 Provider 密钥。
- WebUI 改用 v1 提交接口。网络响应丢失时保留提交 Key，同一操作重试读取原回执，避免重复任务或误变成补充指令。支持 Web Crypto 的页面可在同一标签页刷新后保留未确认 Key，输入草稿仍遵循原有行为；不具备 Web Crypto 的 HTTP 页面仅内存保留 Key。

## 应用接入变化

详见 [API v1](API-V1.md) 和运行中的 `/api/v1/openapi.json`。新增版本入口、结构化错误、关联编号、持久化提交去重与查询、业务来源标签和筛选、配置总览。停止操作绑定目标 runId。

旧 `/api` 保留兼容：已有 news2douyin 和 Video App 可继续使用。来源标签目前不是鉴权主体，独立应用 Token 和授权范围不在本版实现范围。

## 升级

1. 停止旧进程，备份原数据目录。
2. 替换可执行文件，沿用原 `--data`、监听参数、RUNDESK_TOKEN、Codex 路径和运行环境。
3. 重新启动并刷新浏览器。启动不会自动重跑旧任务。旧活跃任务按原行为恢复为 interrupted。

数据存储在现有 SQLite objects/events 表中，新增可选会话来源字段和 api-request 记录；不搬迁工作区、实例目录和原生线程。未确认旧请求不得通过更换 Key 自动重发。

```bash
./bin/rundesk --version
./bin/rundesk --listen 127.0.0.1:3210 --data /path/to/existing-data
```

压缩包包含源码、Linux amd64 可执行文件和 Windows amd64 可执行文件。Windows 仅交叉编译，仍需实机验证。
