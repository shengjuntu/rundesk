# RunDesk 0.30.0 / Kun 0.7.0

本版把 Kun 独立诊断的“补充指令”建议接到现有控制机制：管理员可审核和编辑文本，预览来源当前 run/revision，明确发送并查看后续回执。

- 预览和查询不改变来源；发送前由服务端重新验证成功建议事件和固定证据，客户端不能任意指定目标或控制操作。
- 状态版本变化或原轮次结束后拒绝；不会把旧建议自动发送到新轮次。发送只排队，不解除暂停，不代替 MCP 审批。
- 同一预览重试使用相同 worker requestId。回执丢失时可核对或重试；排队、生效、拒绝及未知结果分别展示，保留控制事件链接。
- 审核历史保存原建议、审核文本、目标版本和回执，支持刷新与宿主重启后的只读查询，不自动启动 worker。
- 检查类、配置类和 Codex 原生建议尚未接通此执行入口；诊断器跨实例选择、真实服务验收、K3 分叉/组合和 K4 优化仍待完成。

Kun 引擎维持 0.7.0、worker 协议维持 v7。0.29.0 升级到本版不改变引擎检查点兼容标识；从 0.28.0 或更早升级仍须同步更新 Kun 并遵守跨引擎检查点限制。Go 1.25.12+ 执行 `make build`，无新增第三方运行时依赖，源码不含二进制。

详见 [诊断与审核](KUN-DIAGNOSIS.md)、[验证记录](KUN-VALIDATION.md) 和 [阶段完成度](KUN-PROGRESS.md)。
