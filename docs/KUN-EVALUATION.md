# Kun 评测：固定输入、规则与重复采样

按固定输入、独立文件目录、产物规则、评分与重复采样组织评测资料。同基线的只读分支评分与 K4 的独立候选验证分别执行；不能把一个流程的通过结果当作另一个流程的授权或业务验收。研究 API 和数据继续保留，旧创建入口不代表当前日常导航。

<a id="task-sets"></a>

## 固定输入任务集

每案例可选 `workspaceFixture`，预先固定输入文件，每次执行在新目录初始化，支持空目录。保存、复制和查看保留完整定义；更多边界见 [独立评测目录](KUN-EVALUATION.md#evaluation-fixtures)。

可选预先固定的 `artifactRules` 已接入案例运行、Skill 门槛和重复对照。完整边界见 [产物规则](KUN-EVALUATION.md#artifact-rules)。原文本规则与不可变定义语义保留。

把多个案例的输入与验收规则保存为一份不可变定义，用于显式固定案例执行。定义支持创建、完整查看、分页列表与复制为新草稿；保存定义本身不启动会话。

已接入固定案例预览、单次执行身份绑定与逐案例评分。K4 还提供独立验证批次、汇总门槛和 Skill 候选启用，见 [K4 工作流](KUN-K4.md)。包含 [多次采样描述性对照](KUN-EVALUATION.md#repeated-benchmarks)，统计推断尚未实现；独立的同基线 rubric 继续独立使用。

<a id="tasksets-1"></a>

### 界面

1. 在管理员工作台点击“评测任务集”。
2. 填写任务集标题，为每个案例填写唯一标识、标题、固定输入和文本验收规则。
3. 点击“保存固定任务集”。保存保持输入与规则的原始空白、大小写和 Unicode 内容；没有自动运行。
4. 点击“读取任务集列表”，选择一份任务集查看全文、时间、ID 和内容指纹。列表不加载案例正文。
5. 在已保存定义下读取执行环境，生成案例执行预览；核对输入与权限后勾选确认执行。通过“读取案例运行记录”查看历史，再读取评分。
6. 修改已有任务集时，点击“复制为新草稿”，编辑后再次保存。生成新 ID 和指纹，原定义保留。

每个案例的文本规则复用 `reply-rules-v1`：包含、不包含、完全等于；另固定要求运行成功结束。此处只保存规则，匹配语义见 [固定规则评分](KUN-EVALUATION.md#branch-scoring)。

<a id="tasksets-2"></a>

### API

全部为管理员专用；应用凭据和成员入口均不可访问。

| 操作 | 含义 |
| --- | --- |
| `POST /api/v1/kun-task-sets` | 只接受 title/cases；必需 Idempotency-Key；保存新的不可变定义 |
| `GET /api/v1/kun-task-sets?offset=0&limit=20` | 按创建顺序倒序分页，只返回 id/hash/title/createdAt/caseCount |
| `GET /api/v1/kun-task-sets/{tid}` | 返回完整固定定义，并校验持久化指纹和结构 |

旧 `/api` 前缀兼容。POST 同一 Key 与同一请求返回同一对象；Key 用于不同请求返回 409。定义无原位修改或删除；执行与评分使用 `/kun-case-runs`，见 KUN-K4.md。服务端生成 schema=1、evaluator=reply-rules-v1、ID、创建时间、案例数与整体 SHA256 指纹；用户不能提交这些字段。顺序也是固定定义的一部分。

示例请求体：

```json
{
  "title": "库存建议",
  "cases": [
    {
      "key": "stocked",
      "title": "库存充足",
      "input": "库存为 100，请给出建议。",
      "rules": [{"kind": "reply_contains", "value": "充足"}]
    },
    {
      "key": "empty",
      "title": "库存为零",
      "input": "库存为 0，请给出建议。",
      "rules": [{"kind": "reply_contains", "value": "补货"}]
    }
  ]
}
```

<a id="tasksets-3"></a>

### 边界与校验

| 内容 | 限制 |
| --- | --- |
| 每集案例数 | 1–20，保留顺序 |
| 案例标识 | 1–64 位 ASCII 字母、数字、点、下划线或连字符；以字母/数字开头；同集中唯一、大小写敏感 |
| 任务集及案例标题 | 各 1–120 Unicode 字符，不能全空白 |
| 每案例固定输入 | 非空白有效 UTF-8，最多 8192 Unicode 字符 / 32 KiB |
| 每案例规则 | 1–12 条；每条最多 2048 字符 / 8192 字节；规则文本合计最多 16 KiB；完全重复规则拒绝 |
| 整集文本 | 标题、案例标识/标题/输入、回复与产物规则、固定文件路径/内容的 UTF-8 字节合计最多 256 KiB；HTTP JSON 请求仍受全局 1 MiB 上限 |
| 列表 | 默认 20，每页最多 50；offset 0–20971520；未知或重复查询参数拒绝 |

不执行输入、规则脚本或正则。保存/查看不访问项目文件或运行日志，不依赖既有会话。已保存定义在宿主重启后保持一致；复制使用完整文本，客户端不提交旧 ID/hash。持久化内容被修改或 schema/evaluator 不兼容时返回 409。没有任务集删除或自动留存清理。

本批验证与阶段完成度分别见 [验证记录](VALIDATION.md)、[开发进度](STATUS.md)。

## 独立目录与固定输入文件

固定案例可选择在新目录中运行，并预先声明输入文件。每个动态样本、快速样本和独立验证案例都获得自己的目录，避免前一例的产物成为后一例的输入。

> 启用 Bash 的实例也不能执行独立文件目录评测；该目录模式不隔离进程或网络。版本与兼容范围见 [Kun 接口](KUN-SEPARATION.md)。

<a id="fixtures-1"></a>

### 定义与执行

在“评测任务集”中勾选“使用独立评测目录”，按需增加固定输入文件。空文件列表表示从空目录开始；未勾选时继续使用既有共享工作区。文件内容保留原始空白和 UTF-8 字节，随不可变任务集保存。复制为新草稿可以修改，原定义和已生成预览不变。

```json
{
  "key": "copy",
  "title": "从固定输入生成结果",
  "input": "读取 input.txt，将内容写入 result.txt，回复完成。",
  "rules": [{"kind": "reply_equals", "value": "完成"}],
  "workspaceFixture": {
    "files": [{"path": "input.txt", "content": "固定输入\n"}]
  },
  "artifactRules": [{"path": "result.txt", "kind": "file_equals", "value": "固定输入\n"}]
}
```

预览显示实际执行目录，但不创建目录、读写文件或调用模型。确认执行后，worker 在项目的 `outputs/<sessionID>/evaluation` 下独占创建新目录，写入固定输入，再提交运行开始事件。模型的内置文件工具与结束时产物检查均以此目录为根；路径使用 `input.txt` 等目录内相对路径。原项目文件不会复制进去，既有项目文件不受这些工具写入影响。

| 内容 | 限制 |
| --- | --- |
| 每案例固定文件 | 0–16 个 |
| 路径 | 安全、可移植的相对路径，最多 512 字节；拒绝上级目录、绝对路径、设备名；忽略大小写的重复与文件/目录前缀冲突也拒绝 |
| 文件内容 | 每文件最多 32 KiB，有效 UTF-8，无 NUL；允许空文件 |
| 合计 | 每案例内容最多 128 KiB；路径和内容也计入整集 256 KiB 文本限额 |
| 工具 | 只支持内置文件工具；配置含 MCP 的实例在预览/启动阶段被拒绝；worker 同时拒绝附加 Skill、诊断、恢复和分叉 |

固定输入初始化属于确认执行的组成部分；模型仍受原有读写权限、审批与预算约束。初始化不计为模型工具调用。

<a id="fixtures-2"></a>

### 单次使用与证据

目录必须不存在。任何已有目录、链接或先前失败留下的部分目录都不会被采用、覆盖、删除或重置。初始化失败后检查原记录，需要重试时创建新案例。目录初始化与 journal 提交不是跨文件系统原子事务；失败可能留下文件，但不会借此重跑同一评测目录。

同一已接受 run 的幂等重试返回原状态，不重新写入固定文件；该会话不能接受第二个 run，也不支持检查点恢复或分叉。对照批次停止后保留在途运行；宿主重启后显式继续会跳过已完成身份，不重置原输出。

`kun/run.started.data.workspaceFixture` 保存模式、实际根目录、固定文件定义 SHA-256、文件数量与内容字节数，不重复保存文件正文。`KunCaseScore.workspaceFixture` 只有在固定日志范围、运行身份、预览目录和输入摘要全部匹配时才返回。必需评分项 `workspace_fixture_ready` 缺证据或记录不完整时为未知，不能按通过计分。产物判定仍采用完成时事件；后续改文件或重启不改历史评分。

<a id="fixtures-3"></a>

### 快速路径与应用边界

快速守卫新增可选 `workspaceMode`，独立目录模式为 `isolated-fixture-v1`。候选仍绑定原逻辑项目、引擎、配置、权限及工具目录，模式必须与全部来源和验证案例一致。每个案例的实际目录不同，固定文件可随案例变化；精确内容由任务集、预览、请求及初始化证据分别绑定。

动态回退继续使用同一个已初始化目录和动作账本，不重置输入或重放成功写入。隔离候选可以独立验证和做重复对照，但即使全部通过，也不能直接启用到共享工作区应用，服务端返回 `skill_evaluation_only`，界面不提供启用入口。常规应用需在实际工作区重新生成并验证候选。

<a id="fixtures-4"></a>

### 范围与升级

这是文件工具目录分离，不是操作系统、进程或网络沙箱。外部本地程序仍可能修改目录；模型服务、缓存与其他外部状态不被冻结。不会自动清理目录，也不提供项目快照、远程副作用隔离或统计显著性。固定输入中本来存在的文件可通过文件规则，仍不能把通过解释为本次新建。

必须一起升级两个程序。worker v16 与 v15 不混用；旧任务集、历史案例和报告可读。旧预览和检查点按 [兼容规则](KUN-SEPARATION.md) 校验，不兼容时重新生成；旧候选需通过当前引擎守卫，必要时重新提炼和验证。新增字段均为可选，省略时保留既有序列化与指纹。没有依赖变更。

本地真实宿主/worker、重启与回退证据见 [验证记录](VALIDATION.md)。

<a id="artifact-rules"></a>

## 固定产物规则与捕获

产物规则属于不可变任务集的案例，在预览和执行前固定；用于评价预期文件，并纳入来源 Skill、独立验证和多次对照的同一评分链路。可选 [独立评测目录](KUN-EVALUATION.md#evaluation-fixtures)，启用后以下路径和捕获均相对此案例的新目录，初始化证据也加入评分。

<a id="artifacts-1"></a>

### 定义与使用

在任务集编辑器为案例增加产物规则，填写工作区相对路径、类型和值。保存后可查看或复制为新任务集；读取、预览、评分都不会重新读取项目文件或启动模型。

```json
{
  "key": "receipt",
  "title": "生成回执",
  "input": "请将已完成写入 receipt.txt，并回复完成。",
  "rules": [{"kind": "reply_contains", "value": "完成"}],
  "artifactRules": [
    {"path": "receipt.txt", "kind": "file_equals", "value": "已完成"}
  ]
}
```

| 类型 | 判定 |
| --- | --- |
| file_exists | 路径是可完整读取且不超过 1 MiB 的普通文件；值省略或为空 |
| file_contains | 文件为有效 UTF-8，包含指定非空文字 |
| file_equals | 文件为有效 UTF-8，与值逐字节相等；允许空文件/空值 |
| file_sha256 | 原始字节 SHA-256 与 64 位小写十六进制摘要相等；可检查二进制文件 |

每个案例 0–8 条产物规则，仍需 1–12 条回复规则。产物值最多 8 KiB UTF-8；规则计入任务集既有 256 KiB 文本总限额。路径最多 512 字节，用 `/` 分隔，不允许绝对路径、上级目录、空段、反斜杠、设备名或特殊字符。

<a id="artifacts-2"></a>

### 捕获与评分

worker 在本次运行成功结束时、提交终态前读取文件。工作区通过 `os.Root` 限定，符号链接不能逃出该根；只接受普通文件，最多读取每个不同路径 1 MiB，同一路径只读一次。读取前后检查文件身份、长度和修改时间，可检测的并发变化标为未知。FIFO 使用非阻塞打开并拒绝，不作为文件内容读取。八条规则最多八个有界文件读取；网络文件系统延迟不在此提供硬性时限。

文件内容只在本次检查内使用，证据不保存原文。`kun/run.finished.data.artifacts` 包含固定规则摘要、每条规则的索引/路径/类型/结果/原因，以及可用时的长度和 SHA-256。证据与结束事件及 worker 状态在同一 journal 事务保存，宿主补取事件即可评分；重启不重新捕获。文件检查不会成为发给模型的工具结果。

案例评分只读与回复评分相同范围的保留事件，并验证运行身份、规则摘要和完整结果。`KunCaseScore.artifacts` 提供有效原始证据；`evaluation` 合并运行成功、回复和文件规则，每条权重相同。原有只含回复的案例行为和序列化保持不变。

| 情况 | 评分行为 |
| --- | --- |
| 缺失文件、目录/非普通文件、内容或摘要不匹配 | 对应规则失败 |
| 日志不全、没有结束时证据、规则摘要不匹配、异常/中断结束 | 产物规则未知；运行失败另由运行成功规则判定 |
| 文件过大、不能读取、文本非法 UTF-8、可检测的读取中变化 | 对应规则未知，不替换为零分或通过 |
| 后来修改、修复、删除文件；宿主重启 | 继续采用原结束事件，历史判定不变 |

只有全部规则通过且无未知的来源/独立验证可进入原有 Skill 门槛。快速执行和动态回退都经过相同终态捕获。对照报告仍只描述观测，不能代替独立晋升报告。未完成 worker 的重开仅记录中断，不把今日文件伪装成当时证据。固定产物案例不能作为新执行恢复或分叉，需另建案例。

<a id="artifacts-3"></a>

### 边界与升级

这些规则证明完成时可观察文件满足指定条件，**不证明本次创建或修改了它**。预存文件也可能通过；相同工作区的并发任务、外部编辑器或后续样本可改变文件。读取不是工作区原子快照，身份/长度/时间检查不能发现所有并发写入。仍需选择允许重复运行的任务，不宜将外部状态变化解释为模型收益。

可选独立目录为每次样本初始化声明文件，不复制或重置共享项目。不提供文件生成来源追踪、项目快照、操作系统/网络隔离、CSV/Office/PDF 结构检查、事实裁判、远程副作用验证或学习型 JEV。同基线事后回复 rubric 继续只评回复，不会事后读取文件补证据。

两程序一起升级。worker v16 与 v15 不混用；旧定义、历史案例和报告可读取。预览、恢复和分叉按实际引擎版本及格式守卫校验；0.16.0 到 0.17.0 的兼容范围见 [Kun 接口](KUN-SEPARATION.md)，不兼容的预览需重新生成。旧 Skill 守卫会因引擎改变回退，需以当前引擎重建来源/候选并重新独立验证。无依赖变更。Windows 已列入交叉编译检查，实际运行行为仍需对应环境验收。

<a id="branch-scoring"></a>

## 同基线固定规则评分

同一来源安全点的两条路径，可以共用一份固定文本规则，在明确的宿主日志范围内评分。报告把规则结果与模型调用、token、耗时和工具模式并列保存；**规则通过不等于事实正确、产物验收通过或优化有效**。

这是运行分支对照的评分基础。此同基线评分不使用模型裁判、脚本、正则或外部事实查询。独立验证集与候选启用由单独的 [K4](KUN-K4.md) 管理。版本与预览兼容范围见 [Kun 接口](KUN-SEPARATION.md)。

<a id="scoring-1"></a>

### 使用

1. 打开“Kun 分叉”的一份固定预览，在“来源与分支对照”下方找到“固定规则评分”。规则可在目标分支启动前创建。
2. 展开“新建验收规则”，填写标题，增加 1–12 条“最终回复包含／不包含／完全等于指定文本”规则。另有固定的“运行成功结束”项。
3. 点击“保存固定规则”。也可点击“读取评分规则”，选择同基线已保存的规则。规则不可修改；编辑表单后须保存为新规则。
4. 读取上方来源/分支或同基线分支对照。评分沿用这一次对照的**两侧宿主上界和内容指纹**，包括有效的零上界。
5. 点击“按当前固定范围评分并保存”。此步只读已保存日志，写入评分报告，不启动 worker、模型、工具或项目文件操作。
6. 查看左右规则明细、完整回复指纹、通过/失败/未知数量、分数和得分差。规则项可打开实际回复或结束事件作为证据。切换对照对象或重新读取范围会撤销旧评分展示。
7. “读取已保存评分”可打开历史报告，即使没有读取当前对照，或来源日志已删除。原事件跳转仍依赖日志保留。

<a id="scoring-2"></a>

### 评分语义

| 项目 | 固定语义 |
| --- | --- |
| 规则基线 | 完整来源快照、来源轮次、安全点、截止、环境与工具目录的合并指纹；拒绝跨基线评分 |
| 完整性 | 沿用对照的连续序号、会话/轮次、启动来源、继承预算与结束记录校验；不完整时所有项未知 |
| 运行成功结束 | 完整日志中 `completed` 通过；`failed/interrupted/cancelled` 不通过；未知或缺失结束状态为未知 |
| 最终回复 | 所选范围内最后一次非规划执行模型响应的新增 assistant 文本；不使用继承回复、规划文字、工具调用或拒绝结果 |
| 后续响应 | 后续 act 请求、空响应、工具调用或拒绝会使早先答案不再是最终回复；不拿早先成功文本补位 |
| 文本匹配 | 使用完整保留回复，按字面匹配；区分大小写、空白与 Unicode 编码，不规范化、不去除 Markdown、不执行正则 |
| 无回复 | 完整范围没有合格最终回复时，所有文本项失败；“不包含”也不能凭无回复通过 |
| 超大回复 | 最终文本超过 256 KiB UTF-8 时，文本项未知；不只检查显示的节选 |
| 单项权重 | 运行结束及每条文本规则各占一项，等权；不把费用或调用量混入规则分数 |
| 分数 | 所有项已知时为 `通过项 / 总项 × 100`；任何未知项使 score 为 null；两侧分数均已知才计算右减左差值 |
| 总体状态 | 有确定失败为 fail；否则有未知为 unknown；全部通过才 pass |

对照界面的回复节选仍限制 2048 字符；评分从**产生同一份对照摘要的那次有界读取**中取得完整文本。不会从截断节选、客户端传入的结果或私有工具录制推断答案。完整回复不额外存入评分报告，只保存其 JSON 字符串 SHA-256 指纹、字节数、事件身份及逐项结果。

token 未报告不影响已经有完整证据的文本规则评分；用量差值仍按对照原规则保留未知。Hybrid、人工假设与 Live 的模式及使用证据仍清楚显示，分数不能证明假设为真或工具在现实中成功。

<a id="scoring-3"></a>

### API 与保留

均为管理员接口；应用 key、成员 runner/viewer 和成员代理拒绝。

| API | 行为 |
| --- | --- |
| `POST /api/v1/kun-rubrics` | `{previewId, expectedPreviewHash, title, rules:[{kind,value}]}`；kind 为 reply_contains/reply_not_contains/reply_equals |
| `GET /api/v1/kun-rubrics?previewId=…&offset=0&limit=20` | 列出该预览同基线的规则摘要，不返回规则文本 |
| `GET /api/v1/kun-rubrics/{rid}` | 完整不可变规则、基线和内容指纹 |
| `POST /api/v1/kun-evaluations` | `{rubricId, expectedRubricHash, previewId, against?, leftThrough, rightThrough, expectedComparisonHash}`；两侧上界必须显式存在 |
| `GET /api/v1/kun-evaluations?previewId=…&offset=0&limit=20` | 列出以该预览为右侧的报告摘要，不返回回复、完整规则或对照 |
| `GET /api/v1/kun-evaluations/{eid}` | 已保存报告；不重新评分、不重新查询来源、不启动执行 |

两个 POST 要求 `Idempotency-Key`。重复同一请求返回同一对象；新 Key 创建新对象。报告包含固定规则全文、完整对照摘要、两侧评分与哈希，读取时检查持久化指纹。新评分时规则/对照哈希不符、固定范围记录已变化或删除返回 409，用户需重新读取并审查范围。重复已完成幂等请求仍可返回当时保存的报告。

比较响应新增 `hash` 和 `baseline.hash`，仅增加宿主字段，不改变 worker。`evaluator=reply-rules-v1` 标识规则语义；`independentValidation=false` 和原对照 `benchmark=false` 始终明确返回。

规则标题最多 120 字符；每条文本 1–2048 Unicode 字符且不能全为空白；12 条总计最多 16 KiB UTF-8，完全相同的重复规则拒绝。相互矛盾的不同规则不自动删改，会如实得到不能全通过的结果。列表每页最多 50 项。日志仍受每侧 4096 事件、32 MiB 总载荷、8 MiB 单事件限制；评分期限 10 秒，报告最多 4 MiB。暂无规则/报告删除和留存清理接口。

<a id="scoring-4"></a>

### 与独立评测的区别

规则可在看到结果后创建；此分支评分接口没有预注册、训练/验证集隔离、自动运行固定输入集或多次采样。分支补充指令、工具假设、模型输出随机性和 Live 外部环境变化依然可能不同。分数只说明选定记录满足多少明确规则，不自动声称哪种组合更优，也不据此安装 Skill、启用快速路径或报告节省比例。

K4 已接入独立验证集、多案例评分和 [多次采样描述性对照](KUN-EVALUATION.md#repeated-benchmarks)；统计推断尚未实现。真实业务与远程服务效果需目标环境验收，测试范围见 [验证记录](VALIDATION.md)，当前缺口见 [状态](STATUS.md)。

多输入案例和规则由 [任务集](KUN-EVALUATION.md#task-sets) 定义，案例执行、独立验证与候选启用由 [K4](KUN-K4.md) 管理，与本页同基线评分接口分别使用。

<a id="repeated-benchmarks"></a>

## 重复采样与对照

固定重复对照：在同一候选的验证任务集上，将动态执行与 Skill 快速路径逐例配对，重复 2–5 次，保存每次运行证据和不可变汇总。质量同时采用固定回复、可选产物规则，以及启用独立目录时的初始化证据。详见 [产物规则](KUN-EVALUATION.md#artifact-rules) 和 [独立评测目录](KUN-EVALUATION.md#evaluation-fixtures)。

这是描述性对照工具。它帮助观察质量、回退和模型用量；不自动启用候选，不代替 [独立验证门槛](KUN-K4.md)，不承诺统计显著或业务收益。

<a id="benchmarks-1"></a>

### 工作台操作

1. 在 **K4 Skill** 工作台读取候选，打开“多次采样对照”。输入标题和每例重复次数，生成固定预览。预览不会创建会话或启动模型、工具。
2. 核对全部输入、固定回复规则、环境、重复次数和顺序。两组的作者输入完全相同，每次使用独立会话及固定 run；系统可能附加该运行专属的产物保存位置。可逐项读取完整有效输入。
3. 勾选整批真实执行确认，点击“开始或继续整个对照批次”。一次确认覆盖整个固定批次，不要求每例重复确认。后台每次只执行一个案例，沿用全局和实例并发限制、进程名额、工具审批及预算。关闭窗口不会停止批次；审批在对应会话处理。
4. 使用“刷新对照进度”查看当前会话。需要暂停后续案例时，点击“停止后续对照调度”：不再接收新案例，已经开始的运行继续。若需停止当前运行，使用对应会话的停止操作。
5. 汇总并保存报告。即使尚未运行，也可保存部分报告，缺失保持未知。后续汇总创建新报告，旧报告不被覆盖。批次记录和报告记录支持分页重开。

所有重复运行都会使用真实工具。共享模式不重置项目文件；启用独立目录时，每次样本从该案例固定文件初始化到新的工具根目录，绝不重置或采用旧目录。两种模式都不重置服务端状态、缓存或外部世界；开始前应选择允许重复执行的任务。一次批次最多 100 次运行、预览合计最多 8 MiB、定义最多 1 MiB、报告最多 4 MiB。每次工具操作仍受既有权限检查。

<a id="benchmarks-2"></a>

### 固定与恢复语义

- 批次与全部私有案例计划在同一数据库事务内保存；任一插入失败都回滚，不能留下部分批次。
- 固定候选 ID/hash、完整任务集快照、实例/工作区配置摘要、每例输入/规则，以及每次 plan/session/run 身份。
- 按重复轮次、案例顺序执行；同一案例相邻轮次交换 dynamic/fast 的先后。案例之间也交替起始组。不是随机化；奇数重复时先后次数不完全相等。
- 两组都是真实执行，动态组不附加 Skill，快速组允许按既有守卫回退。管理员不能通过单案例 start 接口绕过批次顺序。
- 当前宿主只允许一个对照批次调度，其余普通业务仍可使用共享容量。没有名额时等待，不通过扩容绕过限制。已完成样本及时关闭自己的空闲 worker，保留磁盘证据，使超过 16 次运行的批次无需等待空闲回收。
- 启动前重新核对全部身份，派发前重新检查环境。环境漂移阻止尚未启动的案例，不强制改变在途运行。
- 宿主重启后不自动继续调度；读取运行中断的批次显示 interrupted，不启动 worker。重新开始会跳过已经完成的固定运行，等待仍在途的运行，仅接收未开始的计划。
- 一旦遇到失败、中断或删除的案例，批次 blocked，不会重跑或自动进入下一例。先检查原账本；需要新实验时创建新预览。已成功结束但回复规则不通过的案例仍保留并纳入失败计数，后续样本可以继续。
- 停止与派发共用锁：停止回执返回后不会再接收新案例；停止前已接收的案例可能尚在启动或等待审批。

<a id="benchmarks-3"></a>

### 报告如何解释

| 字段 | 含义 |
| --- | --- |
| `status` | complete 表示每个样本的质量证据已知；partial 表示至少一个未知，不代表另一组胜出 |
| `dynamic` / `fast` | 每组总数、通过/失败/未知、通过率、快速完成次数、回退次数 |
| `passRate` | 每例必须成功结束，固定回复、产物及适用的初始化证据全部通过；任何未知存在时为 null |
| `fastCompleted` / `fallbacks` | 依据真实快速完成/回退事件；回退后的成功仍计入 fast 组质量通过，单独显示回退次数 |
| `metrics.modelCalls` | 完整记录中的模型调用次数 |
| `metrics.reportedTokens` | 用量完整时的已报告 token；Provider 缺失用量不能当零；工具内部用量不在此计量中 |
| `metrics.runMillis` | 引擎活动加等待毫秒；不含宿主排队、启动时间，不是端到端服务延迟 |
| `count` / `missing` | 该指标已知及缺失的样本数；均值、最小、最大只覆盖已知样本；无已知样本时均为 null |
| `total` | 只有该指标全部样本已知时给出合计，否则为 null |
| `pairedDelta` | 同案例、同重复序号的 fast − dynamic；仅两侧指标都已知的配对参与；不混用不同样本的均值 |
| `pairs` | 每一配对为 both_pass、both_fail、fast_only_pass、dynamic_only_pass 或 unknown |
| `results` | 每次固定身份、宿主日志游标、事件指纹、完整回复指纹、逐条规则结果、用量和工具摘要 |

评估依次固定各运行日志截止，不宣称所有运行在同一全局时刻取样。每例受既有 4096 事件 / 32 MiB 有界读取约束；证据超限明确报错，不悄悄忽略。评分不启动 worker、模型或工具。

重复使用已有验证集会暴露结果；这不是新的独立盲测。交替先后与独立文件目录不能消除缓存和外部服务差异；同一案例重复也不等于独立同分布样本。没有置信区间、显著性结论、自动胜者、货币费用估算或业务事实/结构化产物裁判。JEV 仍是可选后续项。

### 管理 API

以下操作仅管理员可访问；同时提供 `/api/v1` 与兼容 `/api`。POST 必须使用 `Idempotency-Key`；传输重试复用原 Key，新操作使用新 Key。所有详情和报告都有指纹检查，未知输入或查询字段被拒绝。

| 路径 | 方法与请求 |
| --- | --- |
| `/kun-benchmarks` | POST title、candidateId、expectedCandidateHash、repetitions；返回 benchmark + execution |
| `/kun-benchmarks` | GET candidateId、offset、limit；只返回元数据页，不返回输入/规则/私有配置 |
| `/kun-benchmarks/{bid}` | GET 固定定义和当前调度状态 |
| `/kun-benchmarks/{bid}/start` | POST expectedHash、confirmExecute=true；后台接收整个固定批次 |
| `/kun-benchmarks/{bid}/stop` | POST expectedHash；停止后续调度 |
| `/kun-benchmarks/{bid}/evaluate` | POST expectedHash；创建不可变报告 |
| `/kun-benchmark-reports` | GET benchmarkId、offset、limit；报告元数据页 |
| `/kun-benchmark-reports/{rid}` | GET 不可变报告 |

`start` 回执的 execution 只是接收时状态，幂等重放也返回原始回执。使用 GET 读取最新进度。列表 limit 为 1–50，返回 `hasMore` 和 `nextOffset`。完整结构见 `/api/v1/openapi.json`。
